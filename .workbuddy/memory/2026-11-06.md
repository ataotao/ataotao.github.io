## 已确认的结论（别再重新推导）

- **入库判据：页面或构建运行时读不读。** 读就入库。`英语/题库/九上_U1..U4.jpg`
  是 `SCAN_BASE + "/九上_" + unit + ".jpg"` 直接加载的原卷对照，**必须留**
  （`英语/练习工具/index.html:408`）。历史/道法期中照片页面读的是
  `images/试卷/*.webp`，原图不入库。
- **HTML 大不是问题，源产物漂移才是问题。** A 类（历史/道法/公式记背）完全由
  `工具/core-template.html` / `formula-template.html` + JSON 构建，10637 行的产物
  不需要人去读；B 类（数学 `函数思维脚手架.html`、英语两份 `index.html`→产物在
  另一路径、物理 `物理/源/`）引擎就在页面里，风险是「改了源忘了 build」。
- **数学那份不拆源**：拆成外部 js/css 会毁掉 `file://` 双击可用。防呆靠 `qb.py`
  每次 build 前自动 `.bak`（这就是那 12 个 `.bak-*` 的来源，已 gitignore）。
- `parity.mjs` 的期望值来自真实构建（快照→构建→比对→还原），不另写规则。
  两处必须归一：`generatedAt` 时间戳、CRLF/LF（`core.autocrlf` 让 checkout 出来
  是 CRLF、构建写 LF，git 视作同一文件——不归一会全库假红灯）。
- 钩子启用是**本机一次性**配置：`git config core.hooksPath .githooks`。
  换机器/clone 后要重跑，否则闸门不生效。
