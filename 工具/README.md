# 背记训练器 · 工具链

给 `道德与法治/`、`历史/`（文字考点）、`公式记背/`（数学公式）三个文件夹生成训练器用。**平时不用管这个文件夹**，只有要加页子或改样式时才用。

```
工具/
  core-template.html      文字版引擎（单文件网页模板，数据用 /*DATA*/null 占位）
  formula-template.html   公式版引擎（自带迷你公式排版，不联网也不依赖 KaTeX）
  build.mjs               数据 + 模板 → <科目>/核心考点训练.html | 公式记背/公式记背.html
  merge.mjs               _transcribe/*.json（逐页转录）→ <科目>/考点数据.json
  parse-paper.py          <科目>/images/xxx.docx（带答案的试卷）→ <科目>/试卷数据.json（⑥ 套卷）
  compress-pages.js       <科目>/images/*.jpg → 1600px 宽 WebP（摆正 EXIF 方向、删原图）
  test.mjs                文字版自检：静态检查 + 用 jsdom 跑六个模式
  test-formula.mjs        公式版自检：抠出排版器渲染全部公式（1018 项断言）
  test-ui-formula.mjs     公式版界面自检：用本机 Chrome 真点五个模式（48 项断言）
  shots.mjs               生成 <科目>/预览截图/*.png（有套卷的多截 3–5 张）
  shots-formula.mjs       生成 公式记背/预览截图/*.png
  _transcribe/            逐页转录的原始 JSON（每 3–4 页一个文件）
```

> `compress-pages.js` 和两个 `shots*.mjs` 要 `bun` + `sharp`（截图脚本用本机 Chrome 无头模式）；`merge` / `build` / `test*` 用 `node`；`parse-paper.py` 用 `python` + `python-docx` + `Pillow`。
>
> `build.mjs` 不带参数会重新生成全部三个；只生成某一科：`node 工具/build.mjs 公式记背`。

## 公式版（公式记背）跟文字版有什么不同

- **公式要排版**：数据里写简化 LaTeX（`\frac` `\sqrt` `^` `_` `\text`），模板里有个约 120 行的迷你渲染器，画成 HTML 的分数/根号，所以单文件、离线也能看。
- **挖空用「块级选择」而不是打字**：数学公式靠键盘敲 `√(b²-4ac)/2a` 既慢又没法判分，所以改成每个空从 4 个候选块里点选，3 个干扰项**故意写成常见错法**（漏负号、根号里加号、分母少个 2）。这才是数学记背真正要练的地方。
- **多一个「认一认」**：给公式认名字，专治「两根之和 / 两根之积 / 顶点纵坐标 / 对称轴」互相记串。
- 字段说明见 `公式记背/使用说明.md` 第八节。

## 加页子 / 改内容（文字版）

> ✅ 公式版的例题分步渲染（`stepsHTML`、分组编号、打印分页）和 `cf-11` 的 12 步富文本例题，已经搬回 `工具/formula-template.html` 与 `公式记背/公式数据.json`。模板、数据、产物三者现在一致，**不带参数的 `node 工具/build.mjs` 也可以安全跑全量重建**；只想重建某一科仍可用 `node 工具/build.mjs 历史`。

1. 新页子放进 `<科目>/images/`，接着编号命名（如 `政治_11.jpg`），然后 `bun 工具/compress-pages.js 道德与法治` 压成 WebP。
   手机拍的照片 EXIF 里带方向标记，脚本会 `rotate()` 把方向烤进像素——**不这么做，去掉 EXIF 的 WebP 在浏览器里会横过来**。
2. 按 `_transcribe/` 里现有文件的格式，把新页转成考点卡 JSON（规范见下）。
3. `node 工具/merge.mjs` —— 合并、清洗、按页码排序，产出 `<科目>/考点数据.json`。
4. `node 工具/build.mjs` —— 生成网页（会顺带校验 id 唯一、`【】` 成对、表格列数）。

图片压缩参考值：原页 4096×3072、2–3MB → 1600×2133、100–600KB（省 84%）。正文卡片已经把文字都提出来了，「对照原页」只是核对用，1600 宽足够看清印刷体和手写批注。

只改文字（不改 id）时，练习记录不会丢：记录是按考点 id 存的。

## 考点卡格式

```json
{
  "id": "ls-p1-02",              // 全局唯一，建议 p<页码>-<序号>
  "page": 1,                      // 对应 images/历史_1.jpg
  "unit": "第一单元 文明的产生与古代亚非文明",
  "lesson": "第1课 从原始社会到奴隶社会",
  "node": "知识点1 人类的形成与原始社会",
  "no": "1",                      // 书上条目编号（可省）
  "q": "人类的起源是什么？",       // 翻卡正面；必须能独立成问
  "a": ["约【300万年前】，【古猿】开始直立行走，人类形成。"],
  "star": 1,                      // 1=普通，2=★，3=★★
  "warn": "易错点：……",            // 可选，会分色显示（必背/易错/注意/补充）
  "table": { "head": ["列1"], "rows": [["单元格"]] }   // 可选
}
```

**`【 】` = 挖空点。** 三个模式都从它派生：

- ① 翻卡背：显示成红色高亮
- ② 填空闯：变成输入框判分
- ③ 四选一：正确项 + 从其他考点抽的 3 个干扰项

同义写法用竖线：`【主心骨|领导核心】`。每个要点标 1–3 处、2–10 个字；标整句会让填空题变得没法做。

`warn` 里用 `；` 分隔，前缀决定颜色：`本课必背一句话：…`（蓝）、`易错点：…`（黄）、`注意：…`、其他（灰）。
`merge.mjs` 会把 `本课必背一句话` 单独提成一张不挖空的整句背卡。

## 自检

```powershell
npm i jsdom --prefix _verify        # 首次
node 工具/test.mjs 历史              # 110 条断言：六个模式 + 续练 + 长答案容错 + 套卷/选卷/主观题/结算/打印
node 工具/test.mjs 道德与法治         # 107 条断言（单卷，选卷那两条自动跳过）
node 工具/shots.mjs 历史             # 重新生成预览截图
```

自检会真的操作页面：揭晓答案、填对、填错、看错题本有没有捞回来、搜索能不能过滤、连点下一题会不会崩、套卷答错有没有标红和给解析、结算页能不能跳回错题、退出后能不能回到上次位置。

> 练习位置单独存在 `localStorage` 的 `kss_sess_v1_<科目>`（`saveSess()`），和练习记录 `kss_v1_<科目>` 分开；「清空 / 导入记录」会一起重置。改版后如果队列里的考点 id 被删了，会安全回退到新一轮。

## 套卷（⑥）——一份或多份卷，选择题 + 主观题

科目目录下放一个 **`试卷数据.json`**，`build.mjs` 就会把它注入 HTML，顶部多出「⑥ 套卷」标签；没有这个文件就完全不出现（现在只有公式记背没有）。

数据是**多卷**结构（2026-11-05 起）：`{ "papers": [ {卷1}, {卷2} ] }`，页面顶部按数组顺序出现「选卷」下拉，`papers[0]` 是默认打开的那份。旧的单卷 `{id,name,questions}` 仍然认，会被自动当成 `papers:[那一份]`。

```json
{
  "papers": [
    {
      "id": "ls-mid01", "name": "2026-2027学年第一学期期中·历史（九上）",
      "exam": "", "source": "题库/…/01.jpg–08.jpg",
      "questions": [
        { "no": 1, "id": "ls-mid01-q01", "unit": "第五单元 走向近代",
          "blocks": [{"t":"p","v":"题干……"}],
          "opts": ["A","B","C","D"], "ans": 0,
          "why": {"A":"……正确。","B":"……错误。"}, "sol": "" },

        { "no": 21, "id": "ls-mid01-q21", "kind": "sub", "unit": "综合", "score": 8,
          "blocks": [{"t":"p","v":"材料一……"}],
          "parts": [
            {"ask":"（1）根据材料一……","score":2,"ans":"参考答案……",
             "pts":["采分点1","采分点2"]}
          ] }
      ]
    }
  ]
}
```

- **选择题**：`blocks` 按试卷顺序排（`p` 段落 / `img` 图片 / `tbl` 题表），`ans` 0=A…3=D，`why` 逐项解析，整段解析放 `sol`。
- **主观题**：`kind:"sub"`，没有 `opts`/`ans`，只有 `parts[]`（每小问：`ask` 设问、`score` 分值、`ans` 参考答案、`pts` 采分点）。页面流程是「给材料+设问 → 学生先写 → 点『我写完了，对照答案』 → 展开参考答案 → 逐条勾采分点自评」。**不判分、不进错题本**，只算自评覆盖率（理由见 `docs/plans/主观题训练方案.md` 的 B 方案否决）。
- 题 id 必须全局唯一、跨卷也不能撞（建议 `<卷id>-qNN`）。练习记录按题 id 存，换卷不丢。

`build.mjs` 的套卷校验（任何一条不过就不写文件）：卷 id / name 唯一、题号、id 不重复、选择题 4 个选项且 `ans∈0–3`、有 `why` 或 `sol`、主观题每小问有 `ask`/`ans` 且 `score` 为正、`blocks` 里的图片文件真实存在。

选择题卷可以从解析版 docx 生成（`parse-paper.py` 写的是**单卷**格式，塞进 `papers` 数组即可）：

```powershell
python 工具/parse-paper.py "历史\images\专练01.docx" _新卷.json `
  --id ls-paper02 --name "九上历史·第二套" `
  --imgdir "历史\images\试卷2" --imgbase "images/试卷2/" `
  --override "历史\试卷单元.json"
node 工具/build.mjs 历史
```

解析器自带校验：题号连续、每题 4 个选项且字母是 A–D、`ans` 在范围内、**逐项解析里"正确"那一项必须和【答案】一致**（否定题干"不可能/不正确…"则反过来）、整段解析必须写「故选X」且与答案一致。

单元标签先按 `DEFAULT_UNITS` 里的关键词打分（题干权重 3、选项 1、解析 1，第一名要领先第二名 1.6 倍，否则算「综合」）；判错的写进 `--override` 的 JSON（`{"题号": "单元名"}`）人工覆盖。只有解析版 docx 这条路有这个机制，**照片手录的卷子单元直接写在题里**。

页面行为：一次一题、点选项或按 1–4 判分、答完展开解析（正确项标绿）、回车下一题、可回看已答的题；顶部可按「选卷 / 单元 / 范围（整卷顺序 · 随机 20 题 · 只做错题 · 只做没做过）」筛；一轮结束出结算页（主观题另给采分点自评覆盖率），错题号可点回原题；「打印整卷」输出题干+答案+解析（主观题印设问+参考答案+采分点）的可打印版本。套卷记录存在 `P.paper`（按题 id），跟考点卡的记录分开算，导出/导入记录时一起带走。
