## 一、目标

化学那边已经能回答「这个题型一共多少道、我练了多少、只练没做过的」；物理和数学用的是**另一个渲染族**（`scaffold`，UI 独立），
所以要把同一套口径补上，孩子在三科看到的说法一致。

可观察判据：

1. 模块页每个题型卡显示「覆盖 a/b」+ 进度条 + 百分比；未满 100% 时有「练未覆盖 N」，满了显示「✓ 已全覆盖」。
2. 模块标题下显示整块进度「题目覆盖 a/b（pct%）」与「练没做过的题（N）」入口。
3. 点「练未覆盖」出的题**一定不是**作答记录里出现过的那道（同一 `sig` 口径），某题型抽空自动换下一个，全空提前收尾。
4. 报告页新增「知识覆盖面」：全科合计 + 每个模块一条进度条。
5. `check-training.mjs pools` 通过，容量表与实测一致。

## 三、实测题量（seed 扫描 1..3000，去重口径 = 题干 + 题图哈希）

| 科 | 题型数 | 固定池 | 不设上限 | 说明 |
|---|---|---|---|---|
| 物理 | 53 | **1553 道**（52 类） | 1 类 | 只有 `model.resistance`（电阻与材料）是纯换数字 |
| 数学 | 99 | **2076 道**（82 类） | 17 类 | 判别式、二次函数各题型、写解析式的 7 个题型都是纯换数字 |

物理分模块：认模型 64 / 认量 316 / 算到底 912 / 作图判断 9 / 读数 252。
数学分模块：基础快练 1941 / 写解析式 33 / 大题前两步 37（每个得分点 1 道）/ 本周错题 65。

结论与化学一致：**这套题不是无限题库**，除少数纯数字题型外，一个题型刷几轮就见底 —— 这正是「覆盖率」有意义的原因。

## 四、方案（已实施）

1. **core 增加题目指纹 `sigOf(q)`**：`mod.kind + djb2(题干 + 题图 JSON)`；本周错题只哈希 `cropKey`（不拖几十 KB 的 base64）。
   放在 core 而不是 UI，是为了让「去重 / 覆盖 / 未覆盖抽样」三处用同一把尺子，也让自检脚本能直接调。
2. **core 增加 `POOLS` 表 + `kindPool()`**：`-1` = 不限量（不参与百分比），`0` = 未登记（页面按不限处理）。
3. **作答记录新增 `sig` 字段**（追加，不改旧字段）；老记录没有 `sig` → 单独计数并提示「早期 N 题无指纹未计」，不虚报覆盖。
4. **`pickUncovered`**：随机试 400 个 seed，跳过已做与本轮已出；400 次都撞已做 → 判定该题型已做完。
   不用「扫 1200 个 seed 建题库缓存」（化学的做法），因为这两科单题型池最大 270 道，抽样更省内存也够准。
5. **UI**：模块页/题型卡加覆盖行与按钮；`nocover` 会话模式（题量按未做数封顶、抽空提前收尾、总结页按实际题数算正确率）；
   报告页加「知识覆盖面」；今日页模块卡加覆盖行。
6. **自检**：两科 `check-training.mjs` 加 `pools` 模式（重扫 3000 seed 与 `POOLS` 逐项比对）；
   物理 `--ui` 加 4 项断言（记录带指纹 / 题型卡覆盖 / 练未覆盖不出旧题 / 报告页覆盖面），21 项全过；
   数学 `smoke-ui.mjs` 加覆盖与未覆盖断言。

## 六、已知取舍

- **老记录不进覆盖分子**：加 `sig` 之前的记录只有题型名，无法知道是哪道题；宁可少算也不虚报，页面已明示。
- **纯数字题型不给百分比**：数学 17 类、物理 1 类。它们「换数字就是新题」，给百分比永远到不了 100%，只报练了几道。
- **容量表会漂移**：改生成器后必须跑 `pools` 校验，不要手估。这条已写进 AGENTS.md 和两科使用说明。

## 七、审查（2026-11-23，提交前）

两轴审查（规范 / 需求）独立发现了同一个 **P0**，已修：

1. **「练未覆盖」会误判成做完了（P0）**：原实现随机试 400 个 seed 去「撞」没做过的题，
   大池题型只剩最后 1 道时撞空概率 ≈ 1-(1-1/270)^400 ≈ 23%（数学 ≈ 20%）。
   页面写着「练未覆盖 1」，点进去直接进 summary 说「都做完了」。
   改法：core 新增 `enumerateKind(mod, kind)`（扫 seed 1..3000 按 `sigOf` 去重、按题型缓存，
   最慢题型约 30 ms），`pickUncovered` 改为在枚举表里精确遍历 —— 与化学同一套做法，不再做概率猜测。
   回归用例：预置 269 / 243 条已做记录构造「只剩 1 道」，连点 30 次必须每次都抽到那一道；
   **反向验证过**（换回旧实现，第 1 次就报错）。
2. **容量表与运行时同源**：`check-training.mjs pools` 追加断言「`enumerateKind` 条数 == POOLS」，
   防止分母有 64 道、页面只枚举到 60 道这种「覆盖率永远到不了 100%」的静默错。
3. **老记录文案**：`早期 N 题无指纹未计` → `另有 N 条早期记录无指纹未计`（N 是记录条数，不是题数）。
4. **指纹格式升级的衔接**：`DB.meta.lastRound` 里的旧 `sigs`（`id|题干` 格式）与新哈希指纹永不相等，
   会让「本轮避开上一轮题面」静默失效一轮。已加 `sigv: 2`，版本不符时只保留 `kinds`、丢弃 `sigs`。
5. 清理死参数（`kindStat(mode, …)` 的 `mode` 已不参与筛选）、统一按钮文案为「练未覆盖的题（N）」、
   数学板块随机题的轮内去重键也改用 `MT.sigOf`（一把尺子）。
6. 数学「大题前两步」一个得分点只有 1 道题，`练这个得分点` 本身就是「练那道没做过的」，
   不另开「练未覆盖」入口；做过后显示 `✓ 已全覆盖`（原先不显示）。
