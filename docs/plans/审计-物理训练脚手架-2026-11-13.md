1. **主链路是通的**：8 个页签、今日任务卡、五类练习、逐字段判分/订正/下一题、错题本 1-3-7-14、报告、导出、SVG 全部可走；两条自检命令（含 `--ui` 11 项）全绿，未发现 P0（功能整体不可用）。

## 3. 逻辑梳理

### 3.1 状态机

**视图（`VIEWS`，1609-1613）**：10 个渲染函数，其中 8 个可由页签/hash 到达，2 个是练习态。

```
today ──(页签/今日卡「开始」)──> practice ──(next 且 done>=total)──> summary ──(再来一轮/回今日)──> practice | today
  │                                 ↑
  ├─ model/amount/calc/draw/read ───┘ (startSession)
  ├─ wrong ──(回炉到期的/重做)──────┘ (startWrong/startOneWrong)
  └─ report ──(导出/导入/自检/清空)──> 原地重渲染
practice 内另有一支：S.example=true → renderExample（例题），不参与 done/total 计数
```

- 主视图 → `go(view)`（1614）：只设 `S.view` + `render()` + `scrollTo(0,0)`，**不写 hash**（见 B7）。
- `render()`（1615-1623）：清空 `#app` → 调 `VIEWS[S.view]` → 按 `data-go` 切页签 active（practice 时按 `S.sess.mod`）。
- 首屏（2355-2360）：`location.hash` 取 `view=([a-z]+)`，命中 8 个白名单之一才用，否则 `today`（非法值静默回 today ✓）。

**`S`（1602-1606）字段含义**

| 字段 | 含义 | 谁写 | 谁清 |
|---|---|---|---|
| `view` | 当前视图名（10 个之一） | go/startSession/startWrong/startOneWrong/next/startExample | — |
| `sess` | 本轮会话 | startSession(1793-1796)/startWrong(1809)/startOneWrong(1815)/startExample(1838) | 不主动清 |
| `q` | 当前题（生成题对象或错题本存的对象） | nextQuestion(1823/1827)/startExample(1839) | — |
| `res` | 本题判分结果 `{ok,got,total,res[]}` | submit(2107/2113) | nextQuestion(1830) |
| `answered` | 本题是否已提交（防重复提交） | submit(2113) | nextQuestion(1830) |
| `choice` | 选择题各字段的选中下标 | 选项 onclick(1982) | nextQuestion(1830) |
| `hint` | 是否看过提示（只记录，不影响判分） | 看提示(2010) | nextQuestion(1830) |
| `t0` | 本题开始时间（算 sec） | nextQuestion(1831)/startSession | — |
| `mode` | `'new'` / `'wrong'` | startSession(1789)/startWrong(1808)/startOneWrong(1814) | **startExample 不重置**（B1 相关） |
| `draft` | 当前输入框内容（重绘时回填） | submit(2108)/看提示(2010) | nextQuestion(1831) |
| `lastVals` | 提交时的原始输入（反馈里「你填的是」） | submit(2108) | nextQuestion(1831) |
| `scratch` | 草稿纸开关 | 草稿纸按钮(1999) | **从不清**（跨题保留） |
| `fix` | 订正态 `{fields[],ok,tries}` | submit(2111)/submitFix(2137-2143) | nextQuestion(1831) |
| `example` | 是否在例题页 | startExample(1837) | **只有 startSession(1789) 清** → B1/B2 的根因 |

**`S.sess` 两种形态**

- 生成题一轮：`{mod, kind, total, done, right, t0, prevSigs, round, kindQueue}`（1793-1796）。`round` 就是 `DB.meta.lastRound[mod]` 的同一个对象引用。
- 错题回炉：`{mod:'wrong', kind:null, total:min(due,5), done, right, t0, queue:due[]}`（1809、1815）。没有 `round`，所以不写 lastRound、不参与去重（符合 4.8 第 5 条）。
- 例题：`{mod, kind, total:6, done:0, right:0, t0}`（1838），只是给 `renderExample` 的按钮回跳用。

**`DB`（1549-1563）**

- `{v:1, recs:[], wrong:{}, meta:{created, lastRound:{}}}`；加载时兼容旧记录（`o.recs/wrong/meta` 缺失补默认，`meta.lastRound` 缺失补 `{}`，1556-1557）。
- `recs[]` 写入点只有 `submit()`（2117-2121）：`{ts, mod, kind, kn, ok, got, total, sec, hint, mode, steps}`；订正成功时给最后一条补 `fixed:true`（2139-2140）。
- `wrong{}` 写入点：`addWrong()`（2154-2163，key=`id|prompt前60字`，`n` 递增，`due = now + [1,3,7,14][n-1] 天`）；删除点：`removeWrong()`（2164，回炉答对时 2123）。
- `meta.lastRound[mod] = {at, kinds[], sigs[]}`（1750-1764）。

**今日任务卡（1626-1705）**：`plan` 固定 `calc4 → amount4 → model3 → wrong1 → draw/read2`（1635-1642，`alt` 按 `getDate()%2` 单双日轮换）；`done` 由当日 `recs` 统计（1644-1649，`mode==='wrong'` 记到 `done.wrong`）；`done[p.mod] >= p.n` 打勾（1659）。**没有任何 disabled/门槛**（符合 4.5「不设解锁门槛」）。

## 5. 现有自检没覆盖到的路径（`check-training.mjs` 的盲区）

`--ui` 覆盖：今日渲染（仅文本）、一轮练习（calc）、答错订正（calc.qheat）、错题本（文本）、报告（文本）、导出 JSON、calc 两轮去重、calc/model kind 轮换、lastRound 持久化、draw 按 kind 过滤。
下面这些是它**没有**驱动、而本次发现问题的集中区：

1. **例题页全链路**（`startExample`/`renderExample`）：不测渲染、不测「看懂了，开始练」、不测 draw 例题缺选项图（B3）、不测回车误提交（B2）。
2. **错题回炉全链路**（`startWrong`/`startOneWrong`）：只测「答错进本」，不测到期筛选、due 1/3/7/14 递增、答对移出、未到期 alert、**回炉里点「例题」崩溃（B1）**、**同 kind 不同题合并（B4）**。
3. **输入保留**：切草稿纸 / 点选项 / 订正失败重绘（B5、B12）——`--ui` 的桩里没有「先填再点」的序列。
