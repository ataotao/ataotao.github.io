# 模块头「练未覆盖」改按题型口径 · 2026-11-23

- 状态：**已实施（2026-11-23）**
- 日期：2026-11-23
- 真源：`数学/源/train.ui.js`、`数学/题库工具/smoke-ui.mjs`、`数学/使用说明.md`（只改这里）；
  产物 `数学/数学闪练卡.html` 由 `node 工具/trainer/build.mjs 数学` 生成，不手改（ADR-0003）
- 验收：见「五、验收」

## 一、目标

模块头按钮不再报「剩余情境数」，改报**没练过的题型数**；点进去按题型各抽 1 题。
可观察判据：写解析式只有顶点式有记录（8 条无 `skel` 老记录）时，模块头显示「练没练过的题型（7）」，
题型卡的「练没见过的情境」仍只出现在拱桥建模（1 个），顶点式卡不再出现「练过 8 题」与「还没练」并列的矛盾。

## 二、范围

- **只改**：
  - `数学/源/train.ui.js`：`renderModule()` 模块头按钮与说明文案、题型卡按钮文案、`covLine()` 的 legacy 显示、新增按未练题型开练的函数
  - `数学/题库工具/smoke-ui.mjs`：同步改「练未覆盖」文案断言，补一条模块头题型口径回归
  - `数学/使用说明.md`：覆盖面段落
- **不要动**：产物（`build.mjs` 重建）/ `SKELS`、`POOLS` 与题库数据 / `startNocover()` 的情境逻辑 / 今日任务首题优先未覆盖 / 报告页 / 其他学科 / 依赖
- **相关契约**：无 hash 契约改动；记录结构不改（仍用 `sig` / `skel`）

## 三、现状（锚点）

- `数学/源/train.core.js:2723`：写解析式 8 题型里 7 个 `SKELS = -1`（纯数字随机），只有 `write.arch = 1`。
- `数学/源/train.ui.js:347-368`：`coverOf()` 在 `pool <= 0` 时返回 `open: null`；`coverOfMod()` 只累加 `pool > 0`，所以模块分母只剩 1。
- `数学/源/train.ui.js:283-284`：模块头按钮直接取 `cm.open`，于是显示「练未覆盖的题（1）」——算法没错，口径与文案错位。
- `数学/源/train.ui.js:326-330`：`kindStat()` 数的是非回炉记录，是「练过某题型」的正确判据（顶点式 8 条老记录算练过）。
- `数学/源/train.ui.js:418-426`：`covLine()` 在 `pct == null` 分支没显示 `legacy`，导致顶点式卡上「练过 8 题」与「还没练」并列。
- 已知坑：老记录无 `skel`，**不能**用 `coverOf().done` 判未练（会把顶点式误判成没练，数字变 8）。

## 四、方案

1. 模块头：新增按 `kindStat(mod, id).n === 0` 过滤题型 id 的统计，按钮文案「练没练过的题型（N）」；
   点击走新函数，每个未练题型 `MT.gen` 一道，最多 8 题，全练过则退化为全场随机一轮；预生成 `queue`，复用 `mode:'new'`，不碰 `nocover` 的情境抽取链路。
2. 题型卡：原「练未覆盖 N」改「练没见过的情境 N」（仍只在 `SKELS > 0` 时显示）；`covLine()` 在 `pct == null` 分支补 legacy 提示。
3. 说明文案、smoke 断言同步；重建产物后验收。
