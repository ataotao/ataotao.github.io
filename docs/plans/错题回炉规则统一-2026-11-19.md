# 任务卡：四科闪练卡错题回炉规则统一

- 日期：2026-11-19
- 状态：已完成（2026-11-19）；同日追加「历史错题留档供期末复盘」
- 目标：四科闪练卡（数学/物理/化学/英语单词）采用同一套错题回炉规则，防蒙对，间隔基于真实作答时间戳动态计算；掌握后仍可从作答流水统计整学期曾错过的题。
- **后续规范**：本任务卡是一次性落地记录；生效的强制规范见 `docs/规范/错题回炉统一规范.md`（新项目/页面必须遵守），`AGENTS.md` 有入口指针。

四科**都已用 `Date.now()` 绝对毫秒时间戳**，不存在"昨天/前天/3天前"的日历算法。真正的问题是：间隔阶梯写死、解除判据四科不同、三科一次答对就删（蒙对即可解除）。

## 已确认的设计决策（本会话 grill 结论）

1. **解除判据**：连对 2 次才算掌握；加入行为约束。
2. **间隔算法**：保留 1/3/7/14 阶梯，但每次用**当前实际作答时间戳 + 新阶梯间隔**重算 `due`；跳过几天不补账；答错回退一档。
3. **代码复用**：抽共享错题库模块 `工具/trainer/review.js`，四科产物内联同一份源码；改一处重建四科。
4. **有效答对**：分科用时阈值 + 看提示/看答案/订正后答对均不算有效确认；无效答对连对清零。
5. **手动"已掌握"**：改为"跳过本次"——不删除错题，只把 `due` 推到 1 天后，仍须连对 2 次才移出。

## 统一规则（写死，实现照此）

### 错题条目调度字段（共享模块管理，题目快照字段各科自管）

| 字段 | 含义 |
|---|---|
| `ts` | 首次入库时间戳 |
| `due` | 下次到期时间戳（绝对毫秒） |
| `n` | 累计答错次数（统计/展示/云同步合并取 max，不参与间隔计算） |
| `lvl` | 当前阶梯档位 1..4，对应间隔 `[1,3,7,14]` 天 |
| `okStreak` | 连续**有效**答对次数 0..2 |
| `lastOkAt` | 最近一次有效答对时间戳 |
| `lastAt` | 最近一次作答时间戳（无论对错） |

### 状态转移

- **答错**（任何模式）：`n+1`；`lvl = max(1, lvl-1)`（回退一档）；`okStreak = 0`；`due = now + gap(lvl) * DAY`。
- **有效答对**（`due <= now` 且用时达标且无提示且非订正）：`okStreak += 1`；
  - `okStreak >= 2` → **移出错题本**（mastered）；
  - 否则 `lvl = min(4, lvl+1)`；`due = now + gap(lvl) * DAY`。
- **无效答对**（未到期 / 秒答 / 看提示 / 看答案 / 订正后答对）：`okStreak = 0`；`due = now + gap(lvl) * DAY`（重排，防同日连刷凑次数）；不惩罚 `n`/`lvl`。
- **跳过本次**（原手动"已掌握"）：`due = now + 1 * DAY`；其余字段不变。
- **旧数据迁移**：缺 `lvl` 时按 `clamp(n||1, 1, 4)` 推导；缺 `okStreak`/`lastOkAt` 时补 0；`due` 原样保留，不打乱已有计划。

### 分科有效答对最短用时（`minSec`）

| 科目 | 阈值 |
|---|---|
| 数学 | 选择/填空 ≥3s；写解析式/大题前两步 ≥10s |
| 物理 | 认模型/认量/读数 ≥3s；算到底/作图判断 ≥10s |
| 化学 | 统一 ≥3s |
| 英语单词 | 四选一 ≥1.5s |

阈值由各科配置传给共享模块；共享模块内不硬编码任何分科阈值。

## 追加（2026-11-19）：历史错题留档供期末复盘

用户确认：错题掌握后删除的是待复习条目，作答流水 `recs` 里的每笔 `ok:false` 永久留档（导出/云同步都带走），所以历史没丢，缺的是查看入口。经 grill 定：复用 `recs` 不新增归档、报告页加清单、去掉化学截断。

10. **`everWrong(recs, wrongMap)`**（在 `review.js`）：按 `qid` 聚合作答流水，输出题目标题、累计错/对次数、首错/末错时间戳、是否仍在错题本；错次降序。错题库条目在答错入库时写同源 `qid`（旧条目再次答错时补），用于判断"在错题本/已掌握"。
11. **四科报告页加「曾经错过的题」卡片**：数学/物理/化学显示题目标题+错对比+首末错日期+状态；英语显示词+方向。掌握后那行不消失，只把状态翻成"已掌握"。
12. **去掉 `recs` 截断（两处）**：`kernel.js` 提交段 + 共享 `merge.mjs` 云同步合并段，原都是 `>2000` 砍到 `1500`；只改一处会被另一处抵消。整学期作答是复盘原始依据，两处都去掉；单条约 200 B，几千条在 5 MB 配额内。`merge.test.mjs` 补 2200 条不截断断言（9 组）。
13. **`qid` 字段**：四科答错入库时把提交时算好的 `qid` 写进错题条目（与 `rec.qid` 同源）；数据库键与深链契约不变。

- 边界：升级前就存在、此后再没答错过的旧错题条目无 `qid`，会被显示为"已掌握"——一次性数据瑕疵；清了浏览器存储则无历史，靠导出 JSON 长期保存。
- 验收追加：`review.test.mjs` 的 `everWrong`/`dayText` 用例；英语浏览器 QA 报告页含「曾经错过的词」清单且行数 ≥2。

## 风险与对策

- **旧错题迁移**：用户浏览器里已有 `wrong` 条目缺 `lvl`/`okStreak`，首次读取时迁移；不重置 `due`，避免打乱已排计划。
- **云同步合并**：`merge.mjs` 现有 `ts`/`due` 取 min、`n` 取 max；新字段走通用互补。需在 `merge.test.mjs` 补一条断言。
- **用时阈值误伤**：孩子思考慢不会误伤（只设下限）；秒答会被判无效但不惩罚，只重排 `due`，提示文案说明原因。
