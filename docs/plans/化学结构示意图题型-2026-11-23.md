## 三、方案

1. **五种问法**（`ri(r,0,4)`）：
   ① 三个示意图共涉及几种元素（核电荷数去重，2 或 3 种）；
   ② 该微粒是原子 / 阳离子 / 阴离子（质子数 vs 电子总数）；
   ③ 位于第几周期（电子层数，仅原子）；
   ④ 易得 / 易失 / 既不易得也不易失电子（最外层电子数，仅原子）；
   ⑤ 由示意图写离子符号（电荷数 = 质子数 − 电子数）。
2. **示意图渲染分两层**（照抄配平题既有的 prompt/display 分工）：
   - `prompt` 存纯文本 `（＋17）2 8 7`，`wrongKey = normChem(prompt)[:90]` 依赖它，必须稳定且可读；
   - `display` 存标记 `⟦sd:17|2,8,7⟧`，由 `kernel.js` 的 `rich()` 画成 SVG。
3. **`rich()` 的接入方式**：先把 `⟦sd:…⟧` 换成控制字符占位符，再走原有 `chemRuns()`，最后按序拼回 SVG。原因：`chemRuns()` 会把连续的化学字符段整体吞成化学式 SVG，示意图留在原位会被误吞；控制字符不属化学字符，能可靠充当边界。
4. **尺寸按 1:1 像素渲染**（`width`/`height` = viewBox），不用 `em` 缩放——按 em 缩放时 10px 字号会被压到 3~4px，完全看不清。

## 四、踩到的坑（防复发）

- **转义在多层内联后失真**：最初用 `.replace(/\u0001(\d+)\u0001/g, …)` 拼回占位符，写进文件后正则变成 `/(d+)/`（反斜杠丢失），占位符原样留在题干里，页面显示两个豆腐块 `□□`。改为 `split().join()` 按序拼回 + `String.fromCharCode(1)` 生成占位符，**不再依赖正则字面量转义**。
- 自检抓不到这类问题：`check-flash.mjs` 只跑 core（不跑 kernel 渲染），所以**必须另做渲染核验**：`--dump-dom` 里搜 `.qbody` 的字符，确认没有 `\x01` 残留、有 `<svg class="sd-svg"`。
