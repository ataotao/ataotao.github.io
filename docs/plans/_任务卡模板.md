# 任务卡模板

> **用法**：复制本文件为 `docs/plans/<功能>-<YYYY-MM-DD>.md`，填完再开新会话。
> 任务卡是「开新会话时唯一需要读的东西」——写清楚目标、范围、验收，对话里就只放一个路径。
> 预计 **30 分钟以内**的改动不用写卡，说清三件事即可：改哪、不改哪、怎么验。
> 会话边界与上下文卫生的整体规则见仓库根 `AGENTS.md`「会话与上下文卫生」。

- 状态：**待开始** ／ 进行中 ／ **已实施（YYYY-MM-DD，commit `xxxxxxx`）**
- 日期：YYYY-MM-DD
- 真源：`<源文件>`（只改这里）；产物：`<生成物>` 由 `<命令>` 生成，不手改（ADR-0003）
- 验收：见「五、验收」

## 一、目标

一句话：做完什么算完成。再补一条**可观察的判据**（例：390px 宽下不横向滚动；`qa.mjs` 0 失败；正确率分母不含「看答案」）。

## 二、范围

- **只改**：`路径:行号区间`、`路径2`
- **不要动**：产物 / 题库数据 / 其它学科 / 无关重构 / 依赖
- **相关契约**：改 `#mode=` `#fs=` `#view=` 必读 `docs/plans/开始页与深链契约.md`；数据结构看对应 `data/SCHEMA.md`

> 范围写细一点是划算的：它同时是「别顺手重构」的护栏和「别漏改」的清单。

## 三、现状（给锚点，不贴全文）

- **关键位置**：`文件:行号`，或者「自己 `grep "关键词"` 定位」——**不要**在卡里贴整段代码/整份文件
- **已确认的约束**：localStorage 键名、hash 参数、数据结构字段、历史数据兼容
- **已知坑**：上次改这里踩过什么

## 四、方案（可选）

方案已经想清楚就写 1–3 步；没想清楚就留空，让 agent **先给 3 行方案再动手**，确认后再改。

1. …
2. …

## 五、验收（确切命令 + 期望输出）

从**附 A** 里挑对应的几条填进来。**没写验收命令的卡不算完成。**

| # | 命令 | 期望 |
| --- | --- | --- |
| 1 | `node 英语/语法闪练/build.mjs` | 打印 `✓ 数据校验通过` |
| 2 | `node 英语/语法闪练/qa.mjs <url> .qa-flash` | 退出码 0（0 失败） |

## 六、汇报格式

- 改了哪些文件 + 行号
- 验收命令的实际输出（**只贴末尾几行**）
- 风险 / 没做的事
- 建议下一步

## 附 C：什么时候该开新会话

| 场景 | 做法 |
| --- | --- |
| 刚改完，接着微调（第 2、3 轮） | 留在原会话 |
| 换功能 / 换文件 / 换学科 | 新会话 + 本模板 |
| 老会话上下文超过 15 万 token | 先 `/compact`，或写交接卡后开新会话 |
| 一次性问答、排查 | 新会话，结论写进文件（`docs/plans/` 或 `docs/adr/`） |

**交接卡格式**（老会话搬家用，400 字以内）：目标 / 已确认的结论 / 改过的文件与行号 / 试过但失败的方案 / 下一步 / 不要再做什么。

## 附 D：别做的事

- 不在对话里贴整段任务书、整份文件、整屏日志——写进卡或文件。
- 不手改产物（ADR-0003）；不让训练台插件执行构建或写文件（ADR-0002）。
- 不把「146 条断言 × 3 个入口」每改一次都跑一遍——开发只跑源码版，发布前跑三入口。
- 不顺手重构范围外的代码：任务卡里没写的地方就是不该动的。
- 不装新依赖、不联网取数据，除非任务卡里明确写了。
