# 学习记录格式清点（练习记录数据格式 / 导出导入能力）

> 目的：为「DSH 插件解析各科练习记录导出文件做统计」提供事实清单。
> 方法：只读源码 + 只读数据 JSON，未运行任何构建脚本、未修改任何 HTML/数据文件。
> 清点时间：2026-11-04。行号对应当前工作区文件。

## 0. 结论先行

| 问题 | 答案 |
|---|---|
| 不改各科 HTML，只解析导出文件够不够？ | **不够**。6 个训练器里只有 3 个能导出**记录 JSON**（历史/道法、公式记背、物理）；函数脚手架只导出 **TXT**，英语只导出 **Markdown 错题清单**，今晚急救包**完全没有导出**。 |
| 能拿到的那 3 个 JSON 能否做跨科目统一统计？ | 只能做**「当前累计快照」**级统计（正确率、累计错次、覆盖题量、按科目/单元聚合）。**做不了**：统一时间线、首次正确率（历史/道法/公式）、按知识点聚合（记录里只有 itemId，元数据在 HTML/JSON 数据里不在导出里）。 |
| 是否值得给插件定统一中间格式？ | 值得。但需要各科 HTML 各加 10–30 行导出代码（见 §9.2 建议），否则插件只能做「分科目、各自解析」的降级版。 |

三个硬缺口（跨科目统计的拦路石）：

1. **没有统一 schema/version**：除物理（`version:2`）外，5 个训练器的存储对象都没有版本号。
2. **记录里只有 itemId，没有题目元数据**：`unit / lesson / kp` 都在构建时内联进 HTML 的数据里（历史/道法内联、数学内联在 852 KB HTML、物理题包另存 `物理/题库/pack-*.json`、英语内联），导出文件本身**不含**。
3. **多数科目没有逐次事件时间戳**：历史/道法只有「最后一次答题毫秒数 + 按天聚合」，英语、今晚急救包连时间戳都没有。

## 2. `工具/core-template.html` → 历史 / 道德与法治

一句话：**卡片级聚合计数 + 按天汇总 + 套卷（仅历史有）答题记录；有完整 JSON 导出/导入；没有事件日志。**

### 2.1 键与结构

```js
const SK  = 'kss_v1_'   + DATA.subject;   // 记录，core-template.html:336
const SSK = 'kss_sess_v1_' + DATA.subject; // 续练会话，非记录，导入/清空时一并删
```

```json
{
  "cards": {
    "ls-p1-01": {
      "seen": 3,          // 做过次数（number，必填）
      "ok": 2,            // 累计答对（number）
      "wrong": 1,         // 累计答错（number，答对不清零）
      "streak": 2,        // 连续答对，0–9（number，用来算「熟练/待强化」等级）
      "last": 1762300000000, // 最后一次作答，ms epoch（number）
      "mode": "cloze"     // 最后一次练习模式：recite|cloze|choice|wrong（string）
    }
  },
  "days": {
    "2026-11-04": { "n": 12, "ok": 9 }   // 只用当天总数，不记 wrong
  },
  "paper": {                              // 仅当 DATA.paper 存在（历史有 100 题套卷，道法无）
    "ls-paper01-q001": {
      "seen": 1, "ok": 0, "wrong": 1, "streak": 0,
      "last": 1762300000000,
      "pick": 2,           // 最后一次选项下标（-1=没选）
      "cleared": false      // 手动「我会了，清掉」标记位
    }
  }
}
```

- 必填性：导入校验只要求 `cards` 存在（`if(!d.cards) throw new Error('文件里没有 cards')`，core-template.html:550）；`days` / `paper` 缺失时补空对象（:346-347）。
- 版本号/迁移：**无**。`loadProg()` 只做「缺字段补默认」，不认版本。
- `skim` 字段在 `rec()` 里有定义（:368），但全仓**无任何调用方传 `opts.skim`**，实际不会出现。

### 2.2 导出 / 导入

| 项 | 事实 |
|---|---|
| 按钮 | 「导出记录」「导入记录」（core-template.html:519-520 卡片模式；:1051-1052 套卷模式，同一套函数） |
| 导出顶层形状 | `{ subject, exported, data: P }`（:535） |
| 导出文件名 | `<subject>-练习记录-<YYYY-MM-DD>.json` → `历史-练习记录-2026-11-04.json` / `道德与法治-练习记录-2026-11-04.json` |
| `exported` 格式 | `new Date().toISOString()`（UTC ISO8601） |
| 导入兼容 | 兼容两种：`o.data.cards`（本工具导出）或顶层 `o.cards`（裸 P）（:549） |
| 导入语义 | **整份覆盖**本机记录，并 `clearSess()`；无合并、无冲突处理 |
| 版本校验 | 无（不检查 subject 是否匹配，也不检查文件来源） |

```json
{
  "subject": "历史",
  "exported": "2026-11-04T06:27:11.000Z",
  "data": { "cards": { "...": { } }, "days": { "...": { } }, "paper": { "...": { } } }
}
```

### 2.3 能支撑哪些统计

| 统计项 | 支持 | 说明 |
|---|---|---|
| 正确率 | ✅ | 累计 `ok/(ok+wrong)`；或当日 `days[today].ok/n` |
| 错题 / 错误次数 | ✅ | `cards[id].wrong`、`paper[id].wrong`（套卷另有 `cleared` 手动出库） |
| 按 unit / lesson / node 聚合 | ⚠️ | 记录只有 `cardId`；须用 `考点数据.json`（或 HTML 内 `DATA.cards`）把 id → `unit/lesson/node` 映射。历史/道法都有 `unit`、`lesson`、`node`、`no` 字段 |
| 是否第一次就答对 | ❌ | 只有聚合计数与 `streak`，无事件序列，**无法还原首次结果** |
| 时间信息 | ⚠️ | 有 `last`（最后一次，ms epoch）与 `days`（按本地日期聚合 n/ok）；无逐次时间戳、无单题用时、无起止时间 |
| 练习模式区分 | ⚠️ | 只有「最后一次」`mode`，历史上练过什么模式不可还原 |
| 套卷单选正误 | ⚠️ | 有 `pick` + 数据里的 `ans` 可判最后一次对错；无历史选择记录 |

### 2.4 缺什么

- 缺 `version` / schema 标识、缺 `subject` 之外的科目常量校验。
- 缺题目元数据（`unit/lesson/kp`）→ 插件必须自带「id→元数据」映射表。
- 缺逐次事件 → 无首次正确率、无时间线、无趋势曲线（只能拿 `days` 画日粒度折线）。
- `days` 无 `wrong` 字段 → 按天正确率只能 `ok/n`，不能按天看错误分布。

| 统计项 | 数据层支持 | 导出文件支持 |

## 5. `数学/今晚急救包.html`

```json
{
```

## 9. 判定与建议

### 9.1 「只解析导出文件」是否足够

**分两层结论：**

- **能做的（不改任何 HTML）**：历史、道法、公式记背、物理 4 份记录的快照级统计——
  - 各科累计正确率、累计错题数、覆盖题量（做过多少题）；
  - 按科目、按单元/章节聚合（单元需插件用 `考点数据.json` / `物理/题库/pack-*.json` / `物理/源/data/concepts.json` 做 id→元数据映射）；
  - 物理额外可得：五步命中率、概念掌握度分布、连续练习天数、复习到期清单、单题用时。
- **做不到的**：函数脚手架（无 JSON 记录导出，只有 TXT 且只含部分数据）、英语（只有错题 Markdown）、今晚急救包（什么都没有）；**统一时间线与首次正确率**基本无法跨科对齐。

**结论：不够。** 若目标只是「每科一张累计快照卡」，现在就能做；若目标里有「跨科目趋势/首次正确率/知识点热力」，必须改 HTML（或插件从浏览器 localStorage 直读，但那不属于「解析导出文件」路线，且需要用户逐科打开页面）。

### 9.2 最小改动方案（推荐，按性价比排序）

1. **函数思维脚手架**（最划算，+约 25 行）：把 `DB` 直接导成 JSON，例如
   `{schema:'lt.practice/1', subject:'数学', tool:'fn-scaffold', exportedAt, data:DB}`，文件名 `数学-函数脚手架-记录-YYYY-MM-DD.json`；同时把「导入记录」接上（`replaceAll` 语义照物理实现）。数据层已完备，无需改记录逻辑。
2. **历史/道法 + 公式记背**（各 +15 行）：导出对象补 `schema/version`，并在 `cards` 之外加 `firstOk` 集合（在 `rec()` 里 `if(p.seen===1&&ok)p.firstOk=1`），成本极低、立刻补上「首次正确率」。
3. **物理**（+10 行）：导出入参加一层 `{schema, subject, tool, exportedAt, data: state}`，兼容读取裸 state（旧文件）。
4. **英语**（+30 行）：新增记录 JSON 导出（`store` 直出）+ 记录导入；时间戳只能从现在起累积（历史无解）。
5. **今晚急救包**（+20 行）：新增 `save()` 全量导出；时间戳同样只能从现在起累积。

### 9.3 建议统一中间格式（v1 草案）

```json
{
  "schema": "lt.practice-records/1",
  "subject": "历史",
  "tool": "core-template",
  "exportedAt": "2026-11-04T06:27:11.000Z",
  "app": { "storageKey": "kss_v1_历史", "htmlVersion": null },
  "items": [
    {
      "id": "ls-p1-01",
      "meta": { "unit": "第一单元 文明的产生与古代亚非文明", "lesson": "全书主线", "kp": null },
      "stats": { "seen": 3, "ok": 2, "wrong": 1, "streak": 2 },
      "firstTryOk": null,
      "lastAt": "2026-11-04T06:20:00.000Z"
    }
  ],
  "events": [
    { "ts": "2026-11-04T06:20:00.000Z", "itemId": "ls-p1-01", "ok": true,
      "mode": "cloze", "dim": null, "sec": null }
```

约定：

- `items` 必填（快照，永远可用）；`events` 可选（有事件流的科目填，无则空数组并标 `capabilities.events=false`）。

- 文件名建议 `<科目>-<工具短名>-记录-<YYYY-MM-DD>.json`，但不作为判定依据（内容嗅探优先）。
