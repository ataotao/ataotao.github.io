# 坐标与图象训练：分层图形工具（2026-11-11）

## 起因

孩子在函数题上「点不出 (3, −1)」，一次函数、二次函数的图象也没有直觉。
`诊断与建议-九上期中49分.md` 里「图形变换与坐标」板块 0 组母题、识图薄弱，这条正是空档。

判断：这不是记性问题，是「走格子」这个动作没自动化。所以工具不先讲 k、b 的含义，
而是把「先横后竖」做成一根手指就能完成的动作，做错时在图上画出正确路径。

## 五层设计

| 层 | 练什么 | 交互 | 判分 |
|---|---|---|---|
| L1 找点 | 给坐标在图上点 | 点画布，吸附到格点 | 答错标出「x 要再往右几格」，要求照着点一遍 |
| L2 读点 | 看图说坐标 | 两行数字条（点选，不用打字） | 答对画投影虚线 |
| L3 一次函数 | k 是「右一格升几格」 | 算 y → 点第二点 → 连成直线 | 走格台阶从 b 点出发画出来 |
| L4 二次函数 | 开口／顶点／对称轴 | 三连问 + 求 a | 答完标顶点、画虚线对称轴 |
| L5 综合 | 四层混抽 | 同上 | 无提示 |

- 自适应难度：连对 3 题升一档，答错降一档（`S.diff`，0–3）。
- 每层一轮：L1/L2 10 题，L3/L4 6 题，L5 12 题；结束页给正确率、最高连对和一句下一步建议。
- 探索区：`#lv=line`（k、b 滑块）、`#lv=para`（a、h、k 滑块），不判分，只给手感。

## 版面（2026-11-11 第二版：PC 一屏）

目标：电脑上打开不用滚动，图形、选项、答题结果同时可见。

- 答题屏结构 `<div class="playgrid">`：左 `pane-graph`（画布）＋ 右 `pane-side`（题干／控件／反馈）。
  手机上 `pane-side{display:contents}` 让三块按 题干 → 图形 → 选项 → 反馈 的顺序单列流动。
- `≥880px` 断点转两栏：左 `minmax(0,1fr)`、右 `404px`，图形 `width:min(100%,600px,calc(100vh-130px))`，
  高度跟着视口走，矮屏幕自动缩小而不是把选项挤到屏幕外。
- 纯点击题（L1：每一步都是 `ui:'tap'`）没有选项按钮，右侧会空出一大块，
  所以给 `#screen` 加 `.single`：单列、`max-width:560px` 居中，图形 `min(100%,calc(100vh-275px))`，
  预留出反馈条的位置，答完不跳动。
- 答题中（`body.playing`）隐藏页脚、收紧下边距；桌面端 `scrollbar-gutter:stable`，
  避免反馈出现时滚动条带来的横向抖动。
- 探索页同构（`.exploregrid`）：左图右滑块，滑块紧跟题干而不再被推力到页面底部。

## 出题与推进（2026-11-11 第三版）

**出题：全部现场随机生成，没有固定题库。** `genL1..genL4` 用 `ri/pk` 抽参数，同一层每轮的坐标、
k、b、a、h、k 都不一样；难度档 `S.diff`（0–3）决定取值范围（第一象限 → 带负号 → 坐标轴 → 全 −6..6），
连对 3 题升档、答错降档。L5 从四层随机抽。缺点：不会因为某类题做错而在下一轮多出该类型
（`REC.miss` 只记录、未参与抽题），页脚文案已改成与实际一致的表述。

**推进：一律等孩子点，不再自动跳。** 移除全部 `setTimeout` 自动推进与 `fast` 标记：

| 时机 | 反馈条按钮 |
|---|---|
| 多步题答对中间一步 | 继续 →（`S.pendingStep`，只推进到下一步） |
| 最后一问答对 | 下一题 → |
| 答错（数字/选项） | 下一题 → |
| 点图上点答对（含重做答对） | 下一题 → |

推进统一走 `advance()`：`S.pendingStep` 为真就 `S.step++` 重渲染，否则 `endQuestion(S.first)`。
实际点击校验：L1 10 题 10 次点击、L4 6 题 8 次点击（含 2 次「继续」），五层都能走到结算。

因为「下一题」按钮成了唯一出口，单列（找点题）的图形高度从 `100vh−275px` 收到 `100vh−305px`，
给反馈条留 30px 余量：1366×768 下反馈底边 638 / 视口 673，1440×900 下 770 / 805。

## 先想后画（2026-11-11 第四版）

**问题**：第 4 层的「开口朝哪边」「顶点坐标」「对称轴」三道题，画布上已经把整条抛物线画好了，
答案直接看得见——孩子只要看图念答案，练的成了"认图"，不是"由式想图"，等于没练。

**做法**：给题目加一条 `reveal` 通道，与 `draw` 分开。

- `draw`：出题时就画（坐标点、已给的两点等"题目本身"）。
- `reveal`：**只在本题最后一步判完之后才画**，画布先留空，中央有一行灰字"先在心里把图画出来，答完再对照"。
- `renderStep()` 里 `S.revealed` 为真才把 `reveal` 拼进绘制列表；`judge()` 在
  `S.step === asks.length - 1`（无论对错）时调 `revealGraph()` 补画并置位。
- `nextQ()` 重置 `S.revealed = false`。

落到具体题目：

| 题 | 原先 | 现在 |
|---|---|---|
| `genPara`（开口/顶点/对称轴三连问） | 一上来就画整条抛物线 | 空白坐标系 → 三问答完才画：曲线 + 橙色虚线对称轴 + 顶点标记 |
| `genFindA`（给顶点和过点求 a） | 画出整条抛物线，a 的形状直接看得出 | 只画顶点和一个过点两个标记，a 得算；答完曲线才长出来 |

配套：`genPara` 的三步 `keep` 全部移除（改由 `reveal` 统一画），避免与 `keep` 重复叠字；
顶点标签按 `h` 的正负放到远离 y 轴的一侧（`h < 0` 靠左、其余靠右），`k = 0` 时标签上移 14px，
避免压住坐标轴刻度。

不影响的部分：第 2 层"看图说坐标"、第 3 层"读 k、b"、`genACompare`（比三条抛物线的宽窄）本来就是
**图是题目**，照旧画出来；`#lv=para` 探索区照旧拖动滑块看形状变化。

## 把规则写在题目里（2026-11-11 第五版）

**问题**：第 3 层「走格法」的题干是"从 A 向右走 1 格（x 从 0 变成 1），y 会变成几？"，
解析只有一句"把 x = 1 代入：y = 1×1 − 2 = −1"。两处都让人看不懂：

1. **"向右走"有歧义**：第 1 层"往右走 1 格"意思是水平平移、y 不变，所以孩子答 y = −2 并不奇怪。
2. **没说套哪条规则**：题面和解析都默认孩子知道"y = kx + b 里的 x、b、k 各代表什么"。
3. **解析里的"1×1"**：两个 1 分别是 k 和 x，看的人分不清谁是谁。

**做法**：

- **题干里加一张规则卡**（`.ask .rule`，浅蓝底 + 左边框）：写清"一次函数 y = kx + b：x 每加 1，y 就加 k
  （k 为正往上、为负往下）"，标出本题的 k、b 具体值，末尾再补"代进去就是 y = 2x − 3"——
  通式 → 本题式这一步是孩子真正卡住的地方（看见"直线 y = 2x − 3"没意识到 k=2、b=−3）。规则是方法，答案仍要自己算。
- **规则卡不放公式说明**：k 叫斜率、b 叫截距这类术语解释不写进卡里（会让卡片从 3 行涨到 5 行，孩子直接跳过），
  术语展开留给答错时的 `badMsg`（规则一 / 规则二）。分工：卡片管"套哪条规则"，解析管"怎么展开"。
- **措辞去歧义**：问题改成"从 A **沿直线**往右走 1 格（x 从 0 变成 1），y 变成几？"，
  第二步提示改成"直线上 x = 1 的那个点"。
- **解析分两条路**，对错都给全：
  - `规则一：代入公式` → y = k×x + b = 1×1 − 3 = **−2**
  - `规则二：k 的意义` → x 加 1，y 就加 k = 1；从 −3 加到 −2
- **读 k、b 那道题**同步改：第二问从"从 (0, b) 向右 1 格"改成"图上标的两个点…x 增加了 1，y 增加了几格？"，
  解析写成"k = 纵变化 ÷ 横变化 = (y₂ − y₁) ÷ (1 − 0)"。
- **综合层不给规则卡**（`S.lid === 'L5'` 时不生成），保持"不再提示"的定位。
- 顺带把 `genWalk`／`genReadKB` 的落点限制从 `MIN..MAX` 收到 `MIN+1..MAX−1`，
  第二个点不再贴在图边（原来会出现 (1, 6) 这种顶到边框的点）。

## 顶部公式速查卡（2026-11-11 第六版）

**问题**：规则卡只在第 3 层走格题出现；点、象限、抛物线的规则散在各题解析里，孩子忘了没处查。
但每题都塞说明会把题干撑爆，且固定说明看两遍就被自动忽略。

**做法**：`<header>` 右侧一个「公式」按钮 + 一张覆盖式卡片（`.cheat`），默认 `hidden`。

- **不占每题高度**：面板 `position:absolute; top:100%` 挂在 header 下方，是覆盖层不是流内元素。
  收起态 header 仍是 56px，`scrollHeight == innerHeight` 不变（1440×900／1366×768／1280×720 都验过）。
- **四段内容**：点 (x, y) 先横后竖 · 象限正负号 · 一次函数 y = kx + b（b 是 (0,b)、k 是右 1 上 k、走格法）·
  二次函数 y = a(x − h)² + k（a 管开口、顶点括号取反外面照抄、对称轴 x = h、求 a）。
  呼应第 3 层那条规则卡：卡片末尾写明"第 3 层蓝底的「规则」就是上面一次函数那条"。
- **`max-height:min(72vh,540px); overflow:auto`**：手机 469px 宽时卡片 539px 触顶，内部滚动，不出屏。
- **关闭方式**：再点按钮 / 点卡片外 / 点右上 × / Esc 四路都能关；点卡片内部不关（`stopPropagation`）。
- **"一次性"落在红点**：`localStorage.mathcoord_helpseen` 没值时按钮右上角显示红点，看过一次就撤掉。
  不自动展开——展开会打断答题节奏。
- **综合层（L5）也能点**：L5 只是不主动给规则卡，"主动去查"不算提示，不影响该层定位。

**取舍**：卡片遮住题目是刻意的。改成流内展开会把图形挤小、破坏一屏，而查公式本身就是"停下来看一眼"。
