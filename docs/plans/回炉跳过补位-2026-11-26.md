# 回炉「跳过本题 + 顺补一道」——数学 / 物理 / 化学闪练卡

- 日期：2026-11-26
- 状态：**已完成**（数学 / 物理 / 化学三科已上线，全部验收通过）
- 相关：`docs/规范/错题回炉统一规范.md`、ADR-0010、`工具/trainer/review.js`

## 1. 用户诉求（原话）

> 数学闪练卡和物理闪练卡，回炉错题时，如果遇到难题，允许设置一个跳过的按钮，然后顺补一个未回炉的错题出来，现在的逻辑，只能做题，导致如果 5 题大部分不会，达不到练习的目的

> 化学闪练卡，回炉错题的逻辑也需要增加相同的机制

## 2. 现状（改前）

| 科目 | 回炉入口 | 跳过按钮 | 跳过后 |
|---|---|---|---|
| 数学 | `startWrong()`，取到期题，`total = min(到期数, 5)` | 有「跳过本次」（`__ltReview.skip`） | 只把 due 推到明天，本轮少做一题 → 5 题不会就只能硬扛或提前结束 |
| 物理 | `startWrong()`，同上 | **没有** | 无路可退 |
| 化学 | `startRound(...,'wrong')`，到期题最多 20 | 有「换一题」（`S.sess.total++/done++`），但**不碰调度**，也不补题 | 队列固定，跳过的仍原样留着，本轮提前收尾 |

## 3. 规则（本次新增，写进规范 1.3）

1. **跳过本题**（回炉轮里，手动干预的唯一形式，沿用 `skip()`）：`due = now + 1 DAY`，其余字段不变（连对进度保留）。
2. **顺补**：跳过后从「错题本里本轮还没排过、且不属于本轮队列」的题里补一道进队列，`total + 1`；补位题按 **最近到期优先**。
   本轮做题量不变（跳过 1 道 → 补 1 道），不会被拉长。
3. **补位题按「练习」判**（内核新增 `practice`）：
   - 答对 → 只更新 `lastAt`，**不动** `due / lvl / okStreak`（还没到期，本来就不该算有效确认，更不该把已有连对清零）；
   - 答错 → 照答错处理（规范 1.3「答错（任何模式）」），`n+1`、回退一档、`due` 重排；
   - 若补进来的题**确实已到期**（错题数 > 本轮上限的情况），按正常回炉判，不走 practice。
4. **「全部错题练一遍」维持原口径**，不算补位题。
5. 正确率分母扣掉跳过数（跳过不是答错）。

## 6. 风险

- 补位题改了 `due` 会打乱档位 → 由 `practice` 只读不写 `due` 规避；答错才重排（符合「答错任何模式」）。
- 跳过后 `total` 变化影响进度条与总结文案 → 总结统一按 `答对 / (total - skipped)` 显示。
- 化学 `S.sess` 会进 localStorage 快照 → 补位标记存在队列条目里（`fill:1`），刷新不丢。
