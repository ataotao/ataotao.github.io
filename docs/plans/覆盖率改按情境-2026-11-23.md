# 覆盖率改按「情境」算（三科闪练卡）

- 状态：**已实施（2026-11-23）**
- 触发：家长看到「自检 18600 题」以为孩子要做这么多，追问「是否重复性太多」。
- 结论：那三个数（18600 / 11600 / 19800）是自检脚本每类跑 200 个 seed 的验证次数，**不是练习量**；
  但重复确实严重，覆盖率的分母也选错了。

## 一、实测：题干 ≠ 情境

把题干里的数字全部抹平再去重（同一句话换数值 = 同一道母题）：

| 科 | 题型 | 不重复题干 | 题干骨架（情境） | 一情境几道 |
| --- | --- | --- | --- | --- |
| 化学 | 93 | 3161（固定池 513） | 694（固定池 **435**） | 固定池 **1.2** |
| 物理 | 53 | 1313 | **108**（固定池 105） | **12.5** |
| 数学 | 99 | 23262（固定池 1966） | 923（固定池 **177**） | **11–25** |

典型：物理热量计算 270 条题干只有 3 个情境；数学圆周角 244 条题干只有 4 句话，只是换角度数字；
二次函数平移 2406 条题干 / 143 个情境。化学固定池几乎不重复（1.18），重复集中在 4 个已标「不限量」的题型。

按「每个情境做对 1–2 道就够、最多 3 道」估，覆盖全部情境约 **480 道**（化学 249 / 物理 97 / 数学 131），不是 4000 道。

## 二、问题

原来的覆盖率分母是**题干数**（物理 1553、数学 2076）。孩子做 10 道物理，覆盖率涨 0.6%，
但这 10 道可能已经覆盖 8 个情境（105 的 8%）。分母被「同一句话的第 12 个数字版本」灌水，
既失真、又让人以为永远做不完。

## 三、改法

1. 每科 core 新增 **`SKELS`** 表（每题型的「情境数」，seed 扫描实测）+ `kindSkel()`。
   `POOLS`（题干数）保留，只用于显示「共 N 道变体」。
   - 化学 89 类 / 513 题干 / **435 情境**；专项 15 类 / 142 / **141**
   - 物理 52 类 / 1553 / **105**；数学 82 类 / 2076 / **177**
   - 纯数字随机题型两张表都记 `-1`（不计百分比，只报练过几个情境）
2. 作答记录新增 **`skel`** = 题干抹平数字后的哈希（与 `sig` 并列，不改旧字段）。
   覆盖率按 `skel` 去重：同一情境换个数字再做第 2 遍**不会**让百分比上涨。
   老记录没有 `skel` → 单独计数并在页面标注「另有 N 条早期记录无情境指纹未计」，宁可少算不虚报。
3. 「练未覆盖」改为**只出没见过情境**：枚举题库后按 `skel` 过滤，同一情境的不同数值版本不重复给；
   某题型情境出完自动换下一个，全出完提前收尾。
4. 文案统一为「情境 a/b」，题型卡补「共 N 道变体」，模块头补一句「同一句话换数字算同一个情境」；
   报告页标题改成「知识覆盖面（见过多少个不同情境）」。
5. 自检：四份 `pools` 同时校验 `POOLS`（题干）与 `SKELS`（情境），并校验运行时 `enumerateKind`
   的 `skel` 去重数 == `SKELS`；`selfcheck` 增加核心断言「同一情境两条记录只算 1 个情境」；
   物理 `--ui` / 数学 `smoke-ui` 的大池回归改成按情境分组（预置到只剩 1 个情境，连点 30 次必须每次都抽到）。

## 四、验收（2026-11-23）

- `check-flash pools` 93 类 / 513 题干 / 435 情境 · `check-focus pools` 15 / 142 / 141
- `check-training pools`（物理）52 / 1553 / 105 · （数学）82 / 2076 / 177
- 出题自检：化学 18600 题 · 物理 11600 题 + 1121 项回归 · 数学 19800 题
- 四页 `selfcheck` · 物理 `--ui` 22 项 · 数学 `smoke-ui` · `parity` 一致 · `check-size` 通过
- 无头 Chrome 900 宽截图：物理「情境 2/3 · 共 270 道变体」、数学「情境 2/4 · 共 244 道变体」、不限量题型「还没练 · 数字随机」

## 五、遗留

- 化学的不限量题型里，`intro.opfig`（四图操作判断）按排列组合有 238 个骨架，但孩子只需认 10 种操作。
  自动识别「排列不是新情境」需要题型特定规则，这次没做，仍标 `-1` 只报题数。
- 两科 UI 的 `doneSkels / coverOf / covLine / pickUncovered` 仍有约 130 行重复，与上次记录的抽公共模块是同一件事。
