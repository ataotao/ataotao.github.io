## 2. 内容正确性（题目 / 答案）

### 2.1 【高】`entry.w12q12`：题干是另一道题，问的是这道题的答案

- 位置：`数学/源/train.core.js:2073–2087`（产物 `数学/数学闪练卡.html:2258–2265`）
- 现象：题干照搬 `entry.w12q7` 的网格条件（5×4 网格、AB²=1²+4²…），但字段问
  「P 的坐标是」「A 的横坐标 = k√2，k =」，解析突然引入 `∠PON=45°`、`|OP|=3`、`A(2√2,0)`、
  绕 P 旋转 90°；配图还是那张没有 P、O、N 的网格图。
- 风险：孩子无法作答（题干没有 P/O/N 的任何定义），必错；解析讲的是另一道题，
  比"不会"更糟——会让孩子怀疑自己漏读了条件。
- 建议：按第 12 周卷第 12 题原题重写题干与配图（把 P、O、N、T、旋转条件写进题干）；
  在补好之前先注释掉该条目（`ENTRY` 数组删一项即可，`dailyQueue` 自动适配）。

### 2.2 【高】`entry.w12q17b`：题干被 HTML 吃掉半句

- 位置：`train.core.js:2119`（产物 `数学闪练卡.html:2303`），渲染在 `train.ui.js:441`
  `card.appendChild(h('div', {class:'qbody', html: fracify(q.prompt)}))`
- 现象：题干里写的是 `判断 0<x<5 上离对称轴最远的是哪一端`。`<x<5 上…</span>` 会被 HTML 解析器
  当成一个标签（`<` 后紧跟字母 → 进入标签名状态），一直吞到 `</span>` 的 `>` 为止。
  孩子实际看到的是「…第一步：写出顶点纵坐标，判断 0」——问句没了。
- 证据：把题干按标签剥离后，文本同样停在「判断 0」；探针 P1 能稳定复现。
- 风险：题目不可读；而且这是**系统性隐患**——以后任何题干/解析写 `0<x`、`a<b` 都会中招，
  现有验收完全测不出来。
- 建议：① 该题改写为 `0 &lt; x &lt; 5`（或「x 在 0 与 5 之间」）；
  ② `fracify` 之前先做最小转义（只保留白名单标签 `br/span/b/i`），
  ③ 构建期加断言：题干/解析/选项里出现 `<` + 字母且不在白名单，直接构建失败。

### 2.3 【中】判别式 Δ=0：字段答案与解析互相打脸

- 位置：`train.core.js:364–385`（`genDisc`）
- 现象（实抽）：
  ```
  方程 3x² + 6x + 3 = 0。
  Δ = 0        实数根的个数 = 1
  解析：Δ = 0，有两个相等的实数根。
  ```
  字段标签问「实数根的个数」答 1，同一屏的解析说「有两个」。出现率 10/400 ≈ 2.5%。
- 风险：人教版口径是「Δ=0 时有两个相等的实数根」，孩子按课本答 2 会被判错，
  而解析又告诉他有两个——概念会被教反。
- 建议：标签改成「**不同**实数根的个数」（tip 已有「算 1 个不同根」，只需同步标签），
  或答案改 2 并同步 tip/explain。二选一，别混着用。

### 2.4 【中】反比例：第二问 23% 的答案就写在题干里

- 位置：`train.core.js:134–155`（`genInverse`）
- 现象：`x1 = pick(r, ds)` 没有排除 `x0`。实测 91/400 = 22.8% 的题长这样：
  「图象经过点 (−1, 3)。」→「当 x = −1 时，y =」答案 3。
- 风险：白送一空，还会让孩子形成「代回去就行」的错误习惯。
- 建议：`ds = ds.filter(v => v !== x0)`；并加断言 `x1 !== x0`。

### 2.5 【中】分段函数：第 4 问 47.6% 退化为照抄题干

- 位置：`train.core.js:300–329`（`genPiece`）
- 现象：`cands` 从 `Math.ceil(t1)` 起，**包含 t1**，所以 `xc` 有一半概率等于转折点：
  「过 (9, 43)；之后沿反比例曲线下降，过 (9, 43)」→「下降段上 y = 43 时，x =」答案 9。
  实测 187/400 = 46.8%（探针 P3）。
- 建议：`for (xv = t1 + 1; xv <= 3*t1; xv++)`，并断言 `c0 < y1`。

### 2.6 【中】选择题正确答案位置高度集中

- 位置：
  - `genSecPerim` `train.core.js:1626`：`{type:'choice', ans:0, options:[...]}` 固定顺序 → 200/200 全 A；
  - `genParallelDist` `1647–1657`：同上 → 200/200 全 A；
  - `genCircumCenter` `1668–1691`：第一个字段恒为 A；
  - **`ENTRY` 全表：20 个选择字段里 18 个 `ans: 0`**（只有 `entry.23.2`、`entry.25.2` 是 B）。
- 风险：大题前两步模块里「依据」类选择题**一路点 A 就能拿 90%**，
  这个模块本来是练"下笔先写依据"的，位置固定后完全失去诊断价值。
  （对比：`basisField()` 走 `shuffle(r, picked)`，位置是随机的——说明洗牌写法本来就有，只是没统一用。）
- 建议：`ENTRY` 的静态选项在 `gen()` 里洗牌（`m.items` 分支复制后对 choice 字段做一次 shuffle 并把 `ans`
  改成 `opts.indexOf(原正确项)`）；三个生成器改用 `shuffle(r, ...)`。

### 2.7 【低】因式分解 8% 退化为平方差

- `p + q = 0` 时题干变成「把 x² − 9 分解成 (x+p)(x+q)」，考的是平方差，不是标题写的十字相乘。
- 建议：`if (p + q === 0) q = -q - 1`（保持 b≠0），或把标题改成「因式分解（十字相乘 / 平方差）」。

### 2.8 【低】「直角三角形」当干扰项有歧义

- `SHAPES.none = ['一般三角形','直角三角形']`（`core:560–565`）。等腰直角三角形**是**轴对称图形，
  孩子完全有理由争。建议改成「不等腰的直角三角形」。

### 2.9 【低】分数答案没提示

- 利润题 b = m/dd，70% 是 `1/5`、`3/4` 这类；扇形周长 8.75% 的 k = 2.5。
  标签只写「b =」「k =」，而其他题会写「（可填分数）」。判分本身支持 `1/5`，只是没告诉孩子。
- 建议：统一在这两处标签加「（可填分数）」。

## 3. 输入校验与错误处理

### 3.1 【高】本机记录损坏 → 白屏，且无法自愈

- 位置：`train.ui.js:10–23`（读）、`30–38`（`dayPlan` 写 `DB.meta.dayPlan`）
- 复现（DOM 桩，`.workbuddy-ai/tmp/audit-db.mjs`）：
  ```
  ✗ recs 为对象  → DB.recs.filter is not a function
  ✗ meta 为字符串 → Cannot create property 'dayPlan' on string 'x'
  ```
  载入时只校验了 `o.v === MT.VERSION`，`o.recs = o.recs || []` 对 `{}` 是"真值"，原样留下；
  `o.meta = o.meta || {}` 对字符串同理。之后 `renderToday → todayRecs → DB.recs.filter` 直接抛错，
  `render()` 外层没有 try/catch → 整页空白；**坏数据还在 localStorage 里，刷新继续白屏**，
  而"记录没能存进本机"那条兜底提示根本走不到。
- 建议：
  1. 载入时规范化：`o.recs = Array.isArray(o.recs) ? o.recs : []`、
     `o.wrong = o.wrong && typeof o.wrong === 'object' && !Array.isArray(o.wrong) ? o.wrong : {}`、
     `o.days`、`o.meta` 同理；
  2. `render()` 包一层 try/catch，出错时渲染"记录损坏，点这里备份并重置"；
  3. 兜底按钮：把原始串写进 `mathtrain_v1.bak` 后 `blankDB()`。

### 3.2 【中】错题条目缺 `fields` → 回炉页崩溃

- 位置：`train.ui.js:332–346`（`startWrong` 直接把 `dueList` 的条目塞进 `S.q`），
  渲染时 `renderPractice` 无条件 `q.fields.forEach`。
- 复现：注入 `wrong: {'a|b': {id, prompt, due, ts, …}}`（无 `fields`）→
  `✗ startWrong 崩溃：Cannot read properties of undefined (reading 'forEach')`
- 为什么可能发生：导入路径有 schema 校验（`ui:991` 检查 `Array.isArray(w.fields)`），
  **云同步路径没有**——`sync-adapter` 只校验快照的 `recs` 是数组，`mergeRecords` 原样搬运 `wrong`。
- 建议：`startWrong` 先过滤 `w && Array.isArray(w.fields) && w.fields.length`；
  `mergeRecords` 侧同样校验（两处共用一条规则，别再写第二套）。

### 3.3 【中】带分数被静默算错

- 位置：`train.core.js:45–61`（`parseNum`）
- 现象（实测）：`"2 1/2" → 10.5`、`"1 1/2" → 5.5`。
  原因是先 `.replace(/\s+/g,'')` 再解析分数，`2 1/2` 变成 `21/2`。
- 风险：孩子写带分数是常见操作，这里**不报错、直接判错**，比拒绝输入更坏。
- 建议：先匹配 `^(\d+)\s+(\d+)\s*\/\s*(\d+)$` 按带分数算；或含空格且不是单个数字时直接返回 NaN
  并提示"请写 2.5 或 5/2"。其余边界（`1/0 → Infinity`、`0/0 → NaN`、`1/2/3 → NaN`）都被
  `judge` 的 `isFinite` 挡住，无崩溃，可不改。

### 3.4 【低】两处 HTML 注入

- `train.ui.js:891`：报告页错题本 `h('div', {class:'wt', html: String(w.prompt)…})`。
  `w.prompt` 可能来自导入的 JSON → 恶意/损坏文件可注入标签（自伤型 XSS，风险低但没必要留）。
- `train.ui.js:521–523`：反馈里 `（你填的是 ' + fracify(rawAns(i)) + '）'`，
  `rawAns` 是**用户原始输入**，直接进 innerHTML。输入 `<b>` 会把后文变粗体，输入 `<img onerror>` 会执行。
- 建议：这两处用 `textContent`（或 `h('span', null, txt)`）；题干保留 `html` 但走白名单转义。

### 3.5 【低】导入快照不去重

- `train.ui.js:995–1000`：`dst.qs = dst.qs.concat(src.qs)`。`recs` 走 `mergeRecords` 去重了，
  `days` 没有 → 同一份导出导入两次，"题单快照"当天题数/用时翻倍。
- 建议：按 `(t, p)` 去重，或导入前先清空同名日期。

### 3.6 【低】例题返回后计时不清零

- `train.ui.js:406–414` 恢复现场时没有重置 `S.t0`。看例题花 3 分钟，回来答对这题，记录里用时 +3 分钟，
  会污染报告的平均用时（不影响回炉判定，`minSec` 只判下限）。
- 建议：恢复时 `S.t0 = Date.now()`。

## 4. 题图与题设的一致性

题图分两类（见 `docs/规范/题图显示规范.md`）：`fig.need=1` 是**题设图**，答题前就要看见；
没有 `need` 是**验证图**，答后显示。生成类题目（抛物线/双曲线/线段/分段/点）全部由
`svgFor()` 按参数计算，**坐标与解析式一致，未发现问题**。

问题都在 `ENTRY` 的手绘 SVG（都是 `need:1`，答题前显示）：

| 题 | 位置 | 实测偏差 |
| --- | --- | --- |
| `entry.t12` 圆内接四边形 | core:2010 | 圆 `r=82`；B 距圆心 **70.7**、C **74.7**、D **78.3**——四个顶点只有 A 在圆上 |
| `entry.t05` 圆内证角平分线 | core:1957 | 圆 `r=80`；D 距圆心 **74.3**，D 不在 ⊙O 上（题设要求 C、D 都在圆上） |
| `entry.14.1` 平行得角 | core:1854 | 标注 ∠BOC=80°，图上实际 **43.5°**（C 在 43.5° 方向），弧也只画到 37° |
| `entry.t06` 灯罩轴截面 | core:1972 | 弧顶 y=140，而 H 在 y=30（差 110px）；且 CD:HF 的像素比 142:145 ≈ 1:1，题设是 12:31 |
| `entry.24.1` 正方形旋转 | core:1790 | 正方形画成 110×100；`alpha` 标注在 (146,100)（正方形内部），而 α 是 B 处的角 |
| `entry.t21` 圆锥展开 | core:2039 | 扇形两腰 101 与 95 不等长（应为同一母线） |

- 风险：这些图在**答题前**显示，图错会直接把思路带偏（尤其 t12：孩子会以为"顶点不在圆上也叫内接"）。
- 建议：
  1. 手绘图按题设参数算坐标（圆心 + 半径 + 角度），不要目测；
  2. 加自动断言：解析 `fig.svg` 里的 `<circle cx cy r>` 与各 `<text>` 顶点标签坐标，
     校验 `|dist - r| < 2`；有角标注的校验标注值 ≈ 实际夹角；
  3. 图里没有的字母（如 w12q12 的 P/O/N）单独断言"题干出现的点名，图里必须有"。

## 6. 验收缺口与建议补的断言

配套探针：`node docs/审计/附件/audit-probes.mjs`（本次审计留下的探针，审计当时 9 条告警、
退出码 1；修完后 0 条告警，P1 已转成 `smoke-ui` 的运行时断言，探针里只剩 P2–P6）。

现在 `check-training.mjs` 只做三件事：题干无 `undefined/NaN`、答案有限、正确解判对 / 错解判错。
这挡不住本次全部内容类问题。建议按下面补（都放在 `selfTest` 或独立脚本里，一条一条加）：

1. **题干 HTML 安全**：`/<(?![\/]?(br|span|b|i)\b)/` 命中即失败（能直接抓到 `0<x<5`）。
2. **数学自洽**（按题型写，成本低、收益高）：
   - `inverse`：`x1 !== x0`；
   - `piece`：`c0 < y1`（第 4 问不落在转折点）；
   - `disc`：`Δ===0` 时字段标签必须含"不同"或答案与解析口径一致；
   - `profit`：`0 < 销量`、`0 < 每件盈利`；
   - `path`：`x1 < px < x2`。
3. **选项位置分布**：每个 choice 字段跑 200 次，正确答案落在同一位置的比例 > 60% 就报警。
4. **图形与题设**：`need:1` 的 SVG，按第 4 节第 2 条校验顶点/半径/角度。
5. **退化检测**：题干里已出现的数值不能等于该题任一答案（抓 2.4 / 2.5 这类"白送"）。
6. **DOM 健壮性**：把第 3.1、3.2 的两条崩溃用例写进 `smoke-ui.mjs`（注入损坏 DB / 缺 fields 的错题）。
