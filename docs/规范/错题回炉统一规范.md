# 规范：错题回炉统一逻辑（强制）

- 状态：**生效中**（2026-11-19）
- 适用：**本仓库所有新增和现有的训练项目/页面**，凡涉及"答错 → 间隔复习 → 判定掌握"的错题库，一律遵守本规范。
- 权威实现：`工具/trainer/review.js`（共享内核，唯一规则真相源）。
- 决策背景：`docs/adr/0010-共享错题回炉内核.md`；落地任务卡：`docs/plans/错题回炉规则统一-2026-11-19.md`。
- 术语：`GLOSSARY.md`（连对确认 / 有效答对 / 回炉档位 / 历史错题 / 题目标识）。

> 新增训练页若自建一套错题回炉逻辑（写死 1/3/7/14、答对一次即删、用日历天数判断），视为违反本规范。规则只允许改 `review.js` 一处，改完重建所有接入方并全量验收。

---

## 1. 必须遵守的规则（不得在项目间有差异）

### 1.1 两层数据模型

| 层 | 字段 | 职责 | 掌握后 |
|---|---|---|---|
| **作答流水** `DB.recs[]` | `ts / qid / mod / kind / ok / sec / hint / mode …` | 永久事实层：每答一次记一条，含每次 `ok:false` | **不删**，历史留档供期末复盘 |
| **错题库** `DB.wrong{}` | 调度字段 + 题目快照 | 当前待办层：还没掌握的题 | 连对 2 次有效答对 → 删除该条 |

两层独立。掌握后历史清单里那一行**不消失**，只把状态从「在错题本」翻成「已掌握」。

### 1.2 错题条目调度字段（由共享内核管理）

| 字段 | 含义 |
|---|---|
| `ts` | 首次入库时间戳 |
| `due` | 下次到期时间戳（**绝对毫秒**） |
| `n` | 累计答错次数（统计/展示/云同步取 max；首次入库 = 1，再错才 +1；不参与间隔计算） |
| `lvl` | 档位 1–4，对应间隔 `[1,3,7,14]` 天 |
| `okStreak` | 连续**有效**答对次数 0/1/2 |
| `lastOkAt` | 最近一次有效答对时间戳 |
| `lastAt` | 最近一次作答时间戳（无论对错） |
| `qid` | 题目标识 `模块.题型.题面摘要`，与 `rec.qid` 同源，用于对账是否在错题本 |

### 1.3 状态转移（写死，逐字实现）

- **答错**（任何模式）：`n+1`；`lvl = max(1, lvl-1)`（回退一档）；`okStreak = 0`；`due = now + gap(lvl) * DAY`。首次入库的裸条目（无 `n`）按 `n=1 / lvl=1` 处理，不能记成 2。
- **有效答对**（`due <= now` 且用时达标 且没看提示/答案 且不是订正）：`okStreak += 1`；
  - `okStreak >= 2` → **移出错题本**（mastered）；
  - 否则 `lvl = min(4, lvl+1)`；`due = now + gap(lvl) * DAY`。
- **无效答对**（未到期 / 秒答 / 看提示 / 看答案 / 订正后答对）：`okStreak = 0`；`due = now + gap(lvl) * DAY`；不惩罚 `n`/`lvl`。
- **跳过本次**（手动干预的唯一形式）：`due = now + 1 * DAY`，**其余字段不变**（连对进度保留）；不删除错题。
- **旧数据迁移**：缺 `lvl` 按 `clamp(n||1,1,4)` 推导；缺 `okStreak`/`lastOkAt` 补 0；`qid` 在下次答错时补；`due` 原样保留，不打乱已有计划。

### 1.4 时间戳规则（防"固定天数"）

`due` 永远由**本次实际作答时间戳**算出：`due = now + gap(lvl) * DAY`。禁止用"昨天/前天/3天前"这类日历天数判断；用户跳过几天不补账、不累计欠账，来练时从当前时间重新起算。

### 1.5 防蒙对（有效答对判据）

一次作答只有同时满足以下四条才算有效确认，否则连对清零：

1. 已到期（`due <= now`）——挡同日连刷；
2. 用时 ≥ 本科目/题型阈值——挡秒答蒙对；
3. 没看提示、没看答案；
4. 不是订正提交。

**分科最短用时阈值**（留在各科配置，内核不硬编码）：

| 科目 | 阈值 |
|---|---|
| 数学 | 选择/填空 ≥3s；写解析式/大题前两步（含单空 entry 题）≥10s |
| 物理 | 认模型/认量/读数 ≥3s；算到底/作图判断/手绘 ≥10s |
| 化学 | 统一 ≥3s |
| 英语单词 | 四选一 ≥1.5s |
| 语文背诵·考点默写 | 整句默写 ≥2s |

新科目按题型自定阈值并写在本规范此表（提交改动时同步更新）。

### 1.6 历史留档（期末复盘）

- 作答流水 `recs` **不得截断**（原 `>2000` 砍到 `1500` 的逻辑已废除——提交段和云同步合并段两处都要删，只删一处会被另一处抵消）。
- 报告页必须提供「曾经错过的题」清单：按 `qid` 聚合作答流水，显示题目标题、累计错/对次数、首错/末错日期、状态（在错题本 / 已掌握），按错次降序。共享内核提供 `everWrong(recs, wrongMap)` 与 `dayText(ts)`。
- 错题条目在答错入库时写入 `qid`（与 `rec.qid` 同源），供清单判断"是否仍在错题本"。

## 2. 新项目接入清单（照此顺序做）

1. **接共享内核**：构建时把 `工具/trainer/review.js` 内联成 `<script id="review">`，挂出 `window.__ltReview`（参考 `工具/trainer/build.mjs` 的 5 脚本节点结构：core / review / merge / sync / ui）。自检脚本在跑 UI 段前先 `runInContext` review 段。
2. **提交段改走内核**：`submit()` 里算好 `qid` 与用时 `sec`，写一条 `recs` 事件；再调 `reviewAnswer(q, ok, sec, qid)`。答错时内核 `onWrong`，答对时内核 `onPass` 并传 `{sec, minSec, hint, fixed}`；`onPass` 返回 `'mastered'` 才 `delete DB.wrong[k]`。
3. **配置分科差异**：错题键 `wrongKey(q)`、最短用时 `minSecOf(q)`、题目标识 `qid` 公式留在科目侧；内核不含科目名或阈值常量。
4. **手动按钮**：只提供「跳过本次」（调 `skip`），**不得**提供直接删除错题的"已掌握"按钮。
5. **报告页**：加历史错题清单（用 `everWrong` + `dayText`）。
6. **记录键 / 错题键 / 深链契约**：沿用仓库既有约定（见 `docs/plans/开始页与深链契约.md`）；改键前必须评估开始页统计与云同步影响。
7. **产物不手改（ADR-0003）**：改真源后重建 HTML，跑 `node 工具/parity.mjs` 确认一致。

## 3. 验收命令（新项目必须全部跑通，替换为自己的科目名）

```bash
cd C:/learn/ataotao.github.io
node 工具/trainer/review.test.mjs                 # 共享内核单测（改内核时必跑）
node 工具/trainer/merge.test.mjs                  # 合并单测（含 recs 不截断）
node <科目>/题库工具/check-training.mjs           # 出题自检
node 工具/trainer/selfcheck.mjs <科目>            # UI 运行层自检（含 review 段挂载）
node <科目>/题库工具/check-training.mjs --ui      # 有 UI 桩的科目跑
node 工具/parity.mjs                              # 产物与重建一致
node 工具/check-size.mjs                          # 容量预算
```

**接入自检要点**：四科产物 `<script id="review">` 段逐字节一致（`sha256` 比对）；首次答错入库 `n=1`；秒答/提示/订正/未到期答对均不计连对；跳过本次保留连对；掌握后历史清单行仍在且状态翻「已掌握」；`recs` 超 2000 条不丢最老记录。

## 4. 禁止事项（违反即视为回归）

- ❌ 在项目里另写一套 1/3/7/14 阶梯或到期判断，不走 `review.js`。
- ❌ 一次答对就删错题（蒙对漏洞）。
- ❌ 用日历天数（"昨天/前天/N 天前"）判断间隔。
- ❌ 手动按钮直接删除错题（绕过连对判定）。
- ❌ 截断作答流水 `recs`（提交段或合并段）。
- ❌ 掌握后从历史清单里删除那一行。
- ❌ 在内核里硬编码科目名或用时阈值。
- ❌ 手改产物 HTML 而不改真源。

## 5. 变更流程

规则需要调整时：改 `工具/trainer/review.js`（必要时改本规范 + ADR-0010）→ 重建所有接入科目 → 跑第 3 节全部验收 → 确认四科 review 段仍逐字节一致。**不允许只改一个科目的副本**，那正是本规范要消灭的分叉。
