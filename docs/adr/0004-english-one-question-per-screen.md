# ADR-0004：英语过关用「一题一屏 + 两种判分时机」，题号改为「大题 + 大题内题号」

- 状态：已采纳（2026-11-04）
- 相关：`docs/plans/英语过关练习改版方案.md`、`英语/练习工具/index.html`、
  `英语/练习工具/build.mjs`、`英语/练习工具/data/SCHEMA.md`、
  `英语/练习工具/data/id-migration.json`、`docs/plans/开始页与深链契约.md`、ADR-0001、ADR-0003

## 背景

改版前，一套四张过关卷（U1–U4）被拆成两个互不相干的视图：练习页只放选择题，填空在「填空自测」，
页脚还留一句「本页还有 N 道填空」。原卷是 1–27 连号混排的，所以「按原卷做一遍」这个最基本的用法
在旧架构里不成立。

量化下来有三条硬伤（改版前 Chrome 390×844 实测）：

1. **滚动成本**：U1 整卷 5408px ≈ 6.4 屏；答完一题内联展开的解析块 568px ≈ 2/3 屏，
   下面所有题整体下移。批改报告 12529px、错题本 10688px，手机上基本不可用。
2. **判分时机锁死**：点字母立即判分，`picks` 已答不可改、选项全 `disabled`；唯一反悔路径
   「重做本题」本质是删记录。同时未答也能点「看解析」——答案随时可见。于是「先做完再批」
   在这个架构下不是没做，而是**做不到**。
3. **题号丢了卷面结构**：旧数据按题型拍平后连续编号，大题信息无处安放：U4 的句型翻译
   `(1)(2)(3)` 只能塞进 `note`，U3 语法题重新从 1 编号后新旧「第 1 题」无法区分，
   U2 语法填空的 6 个空没有归属。这次对着扫描原图核对，直接暴露 4 处数据错误：
   U1 第 25 题的选项印在下一页首行（旧数据里这题没有选项）、U1 第 26/27 题被 `build.mjs` 的
   `DROP` 当别卷残片删掉、U2 语法填空 6 空错记在 U3、U4 题号被拍平。

同时有两个约束不能动：`eng9a-practice-v1` 的字段已被 `开始.html` 与训练台读取（ADR-0001 的
「导出快照」路线），不能改键名、不能改字段名；`英语/九上英语过关练习.html` 是产物，只能由
`build.mjs` 生成（ADR-0003）。

## 决定

1. **一题一屏取代滚动长卷。** 一次只渲染一张题卡，底部固定条（`env(safe-area-inset-bottom)`）
   放「上一题 / 提交或下一题 / 答题卡 / 进度 x / N」，做题页另有按大题分组的答题卡抽屉。
2. **两种判分时机，两种模式。** `drill`（过关，默认）：先选后交，点字母只是选中（`picked`），
   `提交` / `Enter` 才判分并展开四段式解析。`exam`（模拟考）：交卷前不给答案与解析，
   可「标记不确定」，交卷后先出结算页（对 X / Y、用时、错题 chips），再逐题讲评。
3. **题号改「大题 + 大题内题号」。** `items[]` 增加 `section`（卷面大题标题，**卷面没有就 `null`，
   不编造**）、`no`（大题内题号）、`fields`（按卷面横线数拆几个输入框）、
   `noLabel`（`(1)` 这类非数字题号）；全局 id = `U{unit}-{sec}{no}`，**无 section 时 `U{unit}-{no}`**
   （U1 因此零迁移）；`unit.passages` 承载大题共享的长文本（`{{1}}`…`{{6}}` 占位），U2 语法填空
   才有。修正后 89 题（40 选择 / 49 填空 / 按空 77）。
4. **33 条 id 迁移，读时重映射、不双写。** 映射表在 `data/id-migration.json`（U3 17 + U4 16），
   `build.mjs` 随数据下发成 `window.__ID_MIGRATION`；加载与导入时对
   `picks/fills/stat/cleared/at/atList/hist` 逐字段改键。**新 id 是唯一真源**，旧 id 只作输入别名，
   导出里不会同时出现两套 id。
5. **记录只追加。** 再答一次 = `stat.att + 1` + `atList` 追加（10 条）+ 新增 `hist`
   （每题最近 5 次 `{a, ok, at}`）；「清空全部作答记录」连 `stat` / `cleared` 一起清（修掉旧版
   清不干净的 bug）。导出外壳仍是 `lt.practice-records/1`。
6. **深链扩到三参数**：`#view=practice|review`、`#mode=drill|exam`、`#unit=U1..U4`；旧 `#view` 值
   全部保留别名，`#layout=one` 静默忽略；仍然只在启动时读一次、不回写地址栏。

## 权衡过的替代方案

- **保留滚动长卷，只做折叠/锚点优化**：不解决任何一个硬伤——解析块照样把后面的题推走 568px，
  答案照样随时可见，两张视图照样把原卷拆开。否决。
- **只做逐题，不加模拟考**：过关练法够用，但要保住「先做完再批」就必须给「看解析」加时机限制，
  那已经等于引入第二种判分时机；只做逐题等于白丢掉「模拟考」这个唯一能自测真实水平的用法，
  还留着一个随时能看答案的洞。否决。
- **不改 id，继续按题型拍平**：零迁移成本、没有串记录风险。代价是原卷大题永远对不上——
  U4 的 `(1)(2)(3)`、U3 语法题的两个「第 1 题」、U2 语法填空的 6 空都只能靠 `note` 打补丁，
  每修一次数据就要人工重新对号（这次一核对就错了 4 处）。迁移是一次性成本，而且 33 条都落在
  `data/id-migration.json` 里可以逐条核对；错号却会永久污染档案。选迁移。
  > 已知缺口：`qa.mjs` 每轮先 `localStorage.clear()` 再从头做，**没有**覆盖「旧存档自动迁移」
  > 这条路——要验迁移得手工造一份旧 id 的 `eng9a-practice-v1` 再打开页面。
- **旧 id 双写（新旧各存一份）**：导出文件里会出现两套 id，训练台按快照统计会重复计数，
  直接违反 ADR-0001「同一工具只取最新快照、绝不重复累加」。否决，改成读时重映射 + 只写新 id。
- **迁移表写成代码里的常量**：能用。但 `build.mjs` 本来就要校验数据（id 唯一、选择题答案在选项内），
  迁移表跟数据放一起（`data/id-migration.json`）更不容易和卷面漂开，也方便人工逐条核对。采纳后者。

## 后果

- 好处：手机上一题一屏，答完不用滚动；答案与解析的出现时机可被 DOM 层断言（模拟考交卷前页面里
  没有答案文本）；大题与卷面题号回到界面上，答题卡能按大题跳题；旧存档打开即自动迁移，用户不用
  做任何事；一次修掉 4 处数据错误（89 题对得上原卷）。
- 代价：一题一屏让「通览全卷」变难，这个需求只能靠答题卡补；两种模式各有一套状态
  （`picks` vs `exam.answers` + `reveals`），交互代码量翻倍；`qa.mjs` 要跟着重写并加一组新断言
  （现在共 69 条），改一次交互就得改断言（ADR-0003 第 4 条）；迁移的验证不靠人工翻存档，
  `qa.mjs` 里有一组「旧 id 存档 → 读取后按新 id 归位」的断言。
- **不可回退点**：id 迁移是单向门。导出文件一旦被训练台读过就进了档案，之后要改 id 只能再补一条
  迁移，不能就地改——这也是把它写进 ADR 而不是只写进方案的原因。
- 明确不做：主观题 / 作文 / 听力 / 自动评分；卷面无分值，只算对题数不算得分；网页发布版隐藏
  「看原卷」（原卷大图不随发布上线）；不做逐题坐标裁剪或页内缩放浮层。
- 与 ADR-0003 的关系：本次改的是源（`index.html` + `data/*.json`），`英语/九上英语过关练习.html`
  仍是产物，只能由 `node 英语/练习工具/build.mjs` 重建，不手改。验收数字：`build.mjs` 汇总
  89 / 40 / 49 / 77、`check-grading.mjs` 无缺答案、`qa.mjs` 77 条断言全过（含旧记录 id 迁移一组）。
