# ADR-0002：训练台是只读的旁路工具，不进项目的关键路径

- 状态：已采纳（2026-11-04）
- 相关：`工具/dsh-plugin/README.md`、`AGENTS.md`

## 背景

「训练台」是一个装进 DSH profile 的 Web 插件（左侧栏入口 + 只读面板），
用来一屏看清六科材料健康状态、跨科待办和学习记录统计。它面对的是**维护者**，
不是孩子——孩子仍然双击各科单文件 HTML。

风险在于：插件装在 `~/.dsh/profiles/<profile>/node_modules`，跟仓库生命周期不同步。
如果它成为「跑构建/改数据」的唯一入口，那么换机器、换 DSH 版本、或删掉插件时，
项目就瘫了。这个仓库要维护到孩子不需要家长协助为止，几年后没人记得插件存在。

## 决定

1. **只读**：插件不写仓库、不跑构建脚本。它只读 JSON/文件状态，另加一组**固定白名单**
   的只读校验命令（`qb.py verify`、`check_answers.py`、`audit_packs.py`、
   `check-grading.mjs`），命令与参数写死在 `index.js` 的 `AUDITS` 表里，
   面板不接受任意命令，`subject` 只能是六科之一。
2. **不进关键路径**：删掉插件，仓库照样能双击使用、照样能按各科 README 构建。
   构建的权威入口永远是各科自己的命令。
3. **源码在仓库里**：插件代码放在 `工具/dsh-plugin/`，以链接方式装进 profile，
   仓库是唯一版本源；升级 DSH 后重装即可。
4. **根目录自定位**：插件以链接安装，优先从 `import.meta.url` 向上找仓库
   （同时存在 `AGENTS.md`、`工具/`、`物理/`），不依赖 DSH 的 workspace 默认目录；
   依次回退到 `config.root` → `LEARNING_TRAINING_ROOT` → workspace → cwd。

## 后果

- 好处：插件坏掉、DSH 升级、换电脑，都不会阻断孩子做题，也不会阻断家长按 README 维护。
- 代价：真正需要「跑构建」时仍要人/AI 记命令。缓解手段是面板只报「哪一科该跑」，
  以及把命令写在各科 README 里，而不是替用户执行。
- 自定位的边界：如果仓库被**复制**而不是链接安装，`import.meta.url` 指向 profile，
  自定位会失败并回退到其它来源；面板会列出尝试过的路径，不会静默出错。
