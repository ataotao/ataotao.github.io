# ADR-0006：站点发布改为单仓 + 推送即发布

- 状态：已采纳（2026-11-18）
- 相关：`ataotao.github.io` 仓的 `tools/README.md`（其「三仓不合仓」结论由本 ADR 取代）、
  `tools/publish.ps1`（本 ADR 后退役）、ADR-0003、ADR-0005、仓库根 `AGENTS.md`「开始页与深链」

## 背景

2026-11-18 实测的发布现状：内容来自**三个各自独立的仓**，站点仓自己不生产内容。

| 仓 | 公开 | 提供什么 |
| --- | --- | --- |
| `ataotao/learn-english` | 是 | 英语内容 + `word_table/vocab-app`（Vite 工程，其 `dist/` → 站点根） |
| `ataotao/learning-training` | 是 | 六个训练器 + `开始.html`（→ 站点 `1/`） |
| `ataotao/ataotao.github.io` | 是 | 站点本体，Pages 从 `master` 发布 |

搬运靠 `tools/publish.ps1`（581 行）：按「文件名 + SHA256」把两个源的产物复制进站点仓，
源路径按「命令行 > `publish.local.json`（按 `COMPUTERNAME` 分机器）> 环境变量 > 自动探测」解析，
最后人工 `-Commit -Push`。站点仓 README 曾明确写过为什么**不**合仓：

> 生产仓库里的大文件（20MB+ docx、`_recon` 中间产物、node_modules、工具链）不进站点，
> 所以没有合并仓库，而是用脚本单向发布。

代价是：改一处内容要跨仓、要记得构建、要记得复制、要记得提交推送；换台机器还要重配路径。
那 581 行里最大的一块复杂度（找路径）**完全由「源在三个地方」制造**。

## 决定

1. **`ataotao/ataotao.github.io` 成为唯一开发 + 发布仓。** `learn-english`、`learning-training`
   搬家后 archive 成只读，remote 保留以便回溯。
2. **目录形态：原样搬，不重整。** `开始.html`、`物理/`、`数学/`、`化学/`、`工具/`、`docs/`、
   `学习记录/` 照原样进根；只新增 `apps/english/`（Vite 工程）与 `_site/`（CI 组装的站点，不入库）。
   中文目录名是「内容即目录」的既有约定，`apps/` 是唯一需要英文的工程例外。
   > 一次改动不要同时动「发布形态」和「目录形态」：`parity.mjs`、`check-size.mjs`、
   > 训练台插件的扫描路径、`pre-commit` 钩子、`core.hooksPath` 全都锚在现有路径上。
3. **URL 形态不变。** 英语 `vite.config.ts` 的 `base` 是默认 `/`，`dist` 里的资源引用是
   绝对路径 `/assets/…`，所以它只能待在站点根；组装时把 `apps/english/dist/*` 铺到站点根，
   训练器产物铺到 `1/`。**域名不迁**（理由见 ADR-0007：记录按 origin 隔离，迁域即清零）。
4. **产物继续入库，CI 不重建产物，只校验。** 训练器分两类：B 类（物理/数学训练脚手架、
   化学闪练卡、语文思维脚手架）引擎与题数据同体，**没有构建步骤**；A 类（历史/道法/公式记背、
   物理思维脚手架、化学思维脚手架）有真源与构建脚本。所以 CI 的职责是：
   跑自检 + `parity.mjs`（产物 ≠ 源重建即**失败**）→ 组装 `_site/` → 部署 Pages。
   不在 CI 重建，是因为 B 类无从重建，且重建会让「孩子双击的那个文件」变成要下载的 artifact。
5. **退役 `publish.ps1` / `publish.local.json` 与 README 的发布说明**，改写为「push 即发布」。
   本地只保留一条只读预览命令，不写仓库。
6. **issue 跟代码走**：`learning-training` 的 issue 用 `gh issue transfer` 迁到站点仓，
   五个 triage 标签一起搬；`learn-english` 本来就没在用 issue。

## 搬运方式（执行前修正，2026-11-18）

原计划用 `git subtree` 搬运，实测**本机 git（`2.56.0.windows.4.niugit`）没有 `subtree` 子命令**，
方案改为两条更基础的操作：

1. **训练仓整体并入**：`git fetch` + `git merge --allow-unrelated-histories`。
   路径保持原样（所有脚本都依赖相对路径，不能加前缀），两个无关历史合成一个。
   冲突面实测极小：两个仓顶层同名条目只有 `.gitignore`。
2. **英语子目录并入**：`git fetch` + `git read-tree --prefix=apps/english/ -u <tree>`，
   只取该子目录的 **67 个跟踪文件**（不带 `node_modules` / `dist`）。
   代价是这部分**没有历史链接**——`learn-english` 归档后仍可 `git log -- word_table/vocab-app` 查。

> 为什么不用 `git filter-branch`：它要么重写源仓历史（不可接受），要么需要一个临时克隆，
> 为一个前端工程的逐文件历史引入这种风险不划算。

## 权衡过的方案

| 方案 | 否掉的理由 |
| --- | --- |
| 保留双仓 + 站点仓 CI 自动拉取 | 满足「发布自动」，但「开发与发布同一个 git 项目」不成立；issue 仍两处 |
| CI 从源重建全部产物（不提交 HTML） | B 类没有构建步骤，一半是空的；孩子双击用的文件变成要下载 artifact |
| 单仓但只放产物，源仍在别处 | 等于把 `publish.ps1` 换个地方放，摩擦一点没少 |

## 后果

- **好处**：「改完 push 一次」天然成立；按机器配源路径的复杂度**归零**（这是过去重复踩的坑）；
  `parity.mjs` 从「我记得跑」变成 CI 硬门；issue、文档、构建脚本与代码同处一仓。
- **代价（明确认下）**：站点仓从「几 MB 产物仓」变成「几十 MB 全量仓」，clone 变慢；
  `docs/`、`_recon/`、原卷 docx 与站点产物挤在一处，必须有 `.gitignore` 与 `check-size.mjs` 兜住；
  改源后**必须**重建产物，忘了会被 CI 拦住——这正是要的门，不是故障。
- **必须在段一验证的风险**：Actions 跑在 ubuntu runner 上时，`qb.py`、`parity.mjs`、
  `物理/工具/check.ps1` 是否可用（`check.ps1` 依赖 `pwsh`，可能要单独装或换等价命令）。
- **顺带修掉的既有缺陷**：英语 `dist` 里内联了百度统计（`hm.baidu.com`），而源码里**没有**；
  重建即静默消失。本 ADR 决定**丢弃**该统计，不再向练习页注入第三方脚本。

## 不可回退的约束

1. 各科 `localStorage` 键名**不变**（`physTrain_v1`、`mathtrain_v1`、`chemflash_v1`、
   `eng9a-practice-v1`、`eng9a-flash-v1` 等）——改键 = 孩子所有记录清零。
2. 训练器产物仍是**单个 HTML**，能 `file://` 双击离线使用。
3. `id="core"` 必须能被 node 抽取（`check-training.mjs` ×2、`check-flash.mjs` 靠它）。
