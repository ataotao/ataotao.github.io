# ADR-0001：学习记录用「导出快照 + 内容嗅探」，不直读浏览器存储

- 状态：已采纳（2026-11-04）
- 相关：`docs/plans/学习记录格式清点.md`、`学习记录/README.md`、`工具/dsh-plugin/records.js`

## 背景

孩子的作答记录存在各科训练器自己的 `localStorage` 里（`kss_v1_*`、`gs_v1_数学`、
`fn_scaffold_v1`、`physScaffold.v2`、`eng9a-practice-v1`、`jjb-*`）。清缓存、换电脑、
换浏览器就没了；也没有跨设备合并。训练台需要这些数据做长期统计（正确率、薄弱点、时间线）。

可选路线有三条：

1. 训练台去读浏览器存储 —— 做不到：训练器是 `file://` 单文件，插件在 DSH 页面里，跨不了源。
2. 每个训练器写一个同步接口，把记录推到仓库 —— 孩子得先跑一个服务，且要处理两台设备合并。
3. 各科「导出记录」成 JSON，手动放进仓库根 `学习记录/`，训练台只读解析。

## 决定

采用第 3 条，并做两条约束：

1. **导出是整份快照，不是增量。** 同一（科目, 工具）留多份文件时，只采用最新一份，
   旧文件列出但标「旧快照，统计时只取最新一份」，绝不把作答次数重复累加。
2. **按内容嗅探，不靠文件名/科目名。** 数学一个科目下有三套完全不兼容格式
   （`gs_v1_数学` 公式、`fn_scaffold_v1` 函数脚手架、`jjb-*` 急救包），文件名和
   科目名都会骗人。判据见清点文档 §8.3；新导出优先用统一中间格式
   `lt.practice-records/1`。

## 后果

- 好处：零运行时依赖、孩子不必装任何东西、训练台可以纯只读；记录进 git 后天然有历史。
- 代价：需要人每周导一次；`localStorage` 里的历史不会自动进档案，只能从导出那天起累积。
- 各科导出能力现状（2026-11-04 补齐后）：历史、道德与法治、公式记背、物理、
  数学·函数脚手架、英语都能导出 JSON；急救包仍无导出。
- 首次正确率：历史/道法/公式的 `firstOk` 从本次改造之后的新作答开始累积，之前的历史补不出来。
- 如果将来要「两台设备合并」，正确做法是在导出格式里带设备标识并做 merge，
  而不是让训练台猜 —— 那需要新的 ADR。
