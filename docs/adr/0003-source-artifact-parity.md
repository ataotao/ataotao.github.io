# ADR-0003：模板、数据、产物三者必须同源；改产物前先把改动回流到源

- 状态：已采纳（2026-11-04）
- 相关：`工具/README.md`、`工具/build.mjs`、`工具/formula-template.html`、`公式记背/公式数据.json`

## 背景

2026-11-03，`公式记背/公式记背.html` 被手改过：例题 `cf-11` 的分步渲染换成 12 步富文本
（法一 9 步 / 法二 3 步，含分组标题与逐行说明），比 `工具/formula-template.html`
与 `公式记背/公式数据.json`（7 步精简版，10-30 之后没动）都新。

后果是一个持续两周的陷阱：`工具/build.mjs 公式记背` 会把富文本例题**静默退回**精简版。
`工具/README.md` 只能写一句「先别跑全量 build」来兜底——这不是机制，是让人记住。

同一时期还有一个反向例子：`工具/test.mjs` 停在 2026-11-02 的期望，
2026-11-03 套卷 UX 改成「回看时空白重做 + 『看上次的答案与解析』按钮」后，
测试在 HEAD 就有 4 条失败（97→82 条），看起来像坏了，实际是期望过期。

## 决定

1. **产物只能由源生成，不允许手改。** 改行为先改 `工具/formula-template.html`
   （或 `工具/core-template.html`）、改数据先改 `公式数据.json`，然后按科目重建。
2. **发现产物里有源没有的东西时，先把差异回流到源，再重建。** 本次把 `stepsHTML`、
   分组编号、打印分页 CSS 搬回模板，把 `cf-11` 的 12 步富文本搬回 JSON；
   逆向校验标准是「产物去掉注入的 DATA 行后与模板逐字节一致」。
3. **构建必须幂等**：同一份源重建两次，产物 SHA256 必须相同（本次三科实测相同）。
4. **改 UX 的同一次提交里改测试。** 过期期望比没有测试更糟：它会训练人忽略红灯。
   本次把 `工具/test.mjs` 两处套卷期望改成新交互，断言数保持 97。
5. 重建后按科目跑自检，数字写进 `工具/README.md`：
   历史 97、道法 60、公式排版 1018、公式界面 48（Chrome）。

## 后果

- 现在「改模板/数据 → 重建」不再吞内容，`node 工具/build.mjs` 全量重建是安全的
  （`工具/README.md` 的 ⚠️ 已改成 ✅）。
- 代价：改一处行为要同时改模板 + 跑四个测试 + 确认 diff 只含预期变化；
  这次的实际收益是找回了仓库里唯一一份 12 步例题数据（它此前只存在于产物里）。
- 教训写进本 ADR 而不是记忆文件：**产物比源新 = 有人在绕过构建改东西**，
  下次见到这种信号，应该先回流再继续，而不是给构建加注意事项。
