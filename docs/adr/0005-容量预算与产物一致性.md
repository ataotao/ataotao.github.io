# ADR-0005：入库只看「运行时读不读」，产物一致性用真实构建校验

- 状态：已采纳（2026-11-06）
- 相关：`.gitignore`、`工具/check-size.mjs`、`工具/parity.mjs`、`.githooks/pre-commit`、`docs/adr/0003-source-artifact-parity.md`

## 背景

2026-11-06 清点：工作区 606 MB，git 跟踪 589 个文件 202 MB，`.git` 232 MB。
其中 119 MB 是「入库但运行时用不到」的二进制：

- `历史/题库/…期中/*.jpg`、`道德与法治/题库/…期中/*.jpg` 共 16 张手机原图 **109 MB**。
  页面读的是 `<科目>/images/试卷/*.webp`，原图只在录入阶段用一次。
- 5 个 `预览截图/` + 英语两份 `preview/` 共 89 张 PNG **9.8 MB**，由 `工具/shots*.mjs` 可重建。

同类决定其实已经做过一次（数学期中 4 张原图 41 MB 不入库，仓库只留 `_原卷缩图/`），
但它只以一条 `.gitignore` 注释的形式存在，没有变成规则——于是后面两科照原样提交了原图。
**没有闸门的约定不是约定，是运气。**

同时，四类 HTML 的维护面并不相同，混在一起谈「文件太大要不要拆」会得出错误结论：

| 类 | 例子 | 维护面 | 行数是否是障碍 |
| --- | --- | --- | --- |
| A 完全构建 | 历史/道法/公式记背（`工具/core-template.html`+JSON） | 模板 + 数据 | 否，产物是编译结果 |
| B 引擎手写在 HTML | 数学 `函数思维脚手架.html`；英语两份 `index.html`→产物在另一路径；物理（源在 `物理/源/`） | 引擎就在页面里 | **是**，但问题在「源与产物漂移」，不在行数 |
| C 手写单文件 | 数学 `今晚急救包.html`、物理 `今晚急救速练.html`、`开始.html` | 文件本身 | 26–137 KB，属正常规模 |

ADR-0003 立的验收标准（「产物去掉注入的数据后与模板逐字节一致」）只覆盖 A 类，
B 类（英语、物理）没有任何检查，于是「改了 `index.html` 忘了 build」这个坑原样留在那儿。

## 决定

1. **入库判据只有一条：页面或构建在运行时读它吗。** 读就入库，不读就本机留档。
   不用「这个文件很重要所以放仓库」作为理由——重要性和是否参与运行是两件事。
2. **三类二进制分别处置**：原卷照片只留 webp 或缩图；界面截图不入库（可重建）；
   运行时真读的原图留（`英语/题库/九上_U*.jpg` 是「原卷对照」直接加载的，属此类）。
3. **闸门做成硬钩子**：`.githooks/pre-commit` → `工具/check-size.mjs`。
   新增单文件 > 2 MB 拒绝、位图 ≥ 300 KB 警告、全库 > 200 MB 拒绝。
   规则与阈值只写在脚本头部一处。
   **钩子配置是机器级的**（`core.hooksPath` 不随 clone 传过来），所以配了两层：
   本机一条命令 `node 工具/setup.mjs`（幂等，装钩子 + 体检）；
   服务器一层 `.github/workflows/repo-budget.yml`（每次 push + 每月 3 日跑同一套检查，
   不依赖任何本机设置）。前者早一步、后者忘不了。
4. **产物一致性用真实构建做期望值**（`工具/parity.mjs`）：快照 → 跑构建 → 逐字节比对 → 还原。
   不给检查器另写一份「模板长什么样」的规则——那会变成第二个会漂移的源。
   比对前归一两处噪声：`generatedAt` 时间戳、CRLF/LF。
5. **构建产物继续入库**（HTML、`pack-全部.json`、`bundle.js`）：单次重建 1 MB 级、
   实测重建频率低，换来「clone 下来双击就能用」和发布链路不依赖本机构建。
   真正的容量风险是图片，不是这几百 KB 的 JSON/HTML。
6. **数学 `函数思维脚手架.html` 明确为 B 类且不拆源**：引擎与产物同体，改 UI 就是改产物，
   parity 对它无意义；防呆靠 `qb.py` 每次 build 前自动 `.bak`。
   不把引擎拆成外部 js/css——那会毁掉 `file://` 双击可用这条底线。

## 后果

- 跟踪体积 202 MB → 82 MB；`.git` 232 MB → 96 MB（56 个提交全保留，路径已从全部历史抹除）。
  重写只做一次，之后 clone 变小；GitHub 端的体积统计要等它自己 gc 才更新，这一步不回收服务端残留。
  重写前做了全量备份 `C:\learn\backup\learning-training-before-shrink-20261106.bundle`（219 MB），
  验证过 "records a complete history"。
- 代价一：加页子多一道闸门；原卷照片只在本机，换机器要单独搬（归档在
  `C:\OneDrive\陶宸欣\学习资料\题库`，同构目录，拷回来即还原）。
- 代价一之补充：新机器上没跑 `node 工具/setup.mjs` 时，提交不经过闸门——
  这时只有 CI 会发现，即在 push 之后。这是"本机钩子天生不随 clone 走"的固有缺口，
  用两层冗余换来的结果是：缺口存在，但不会持续太久。
- 代价二：`parity.mjs` 要跑真实构建（数秒），所以放在「改完源、提交前」手动跑，
  不进 pre-commit（钩子里跑构建会写文件，与 pre-commit 的只读约定冲突）。
- 仍存在的隐患：B 类里的数学引擎没有自动化保护，只有 `.bak` 与纪律；
  英语双份产物的漂移现在能被 parity 抓到，但「改完 index.html 忘了 build」仍需靠这条命令发现。
