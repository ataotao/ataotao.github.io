# ADR-0007：学习记录跨设备同步走 GitHub 私有仓，不做数据库服务

- 状态：已采纳（2026-11-18）
- 相关：ADR-0001（其「不做同步接口」的前提由本 ADR 取代）、`docs/plans/学习记录格式清点.md`、
  ADR-0006、`GLOSSARY.md`「同步载体 / 设备标识 / 事件并集合并」

## 背景

记录只存在各设备浏览器的 `localStorage` 里，清缓存、换电脑、换浏览器就没了。
ADR-0001（2026-11-04）处理过这件事，结论是「导出快照 + 内容嗅探」，并明确写下两条：

> - 如果将来要「两台设备合并」，正确做法是在导出格式里带设备标识并做 merge，
>   而不是让训练台猜 —— 那需要新的 ADR。
> - 当时否掉的那条路线是：**每个训练器写一个同步接口，把记录推到仓库 —— 孩子得先跑一个服务。**

本 ADR 就是那条预告的新 ADR。它要处理的前提已经变了：那个被否掉的路线，代价是「孩子得先跑一个
**本地**服务」；而如果记录写到**托管的云**（不需要任何本机进程），这条代价消失。

同时有一个必须先纠正的误解：**GitHub Pages 上不存在「部署 sqlite 数据库」这回事。**
Pages 只发静态文件，没有常驻服务端进程，没有任何东西能接收页面写库的请求。
在页面上跑 `sql.js` / `wa-sqlite`（哪怕配 OPFS）只能得到**每台设备各自的本地库**——
同步问题一个字都没少，只是把 `localStorage` 换了个壳。

所以真问题是：**换设备后记录怎么合**，sqlite 只是可能的手段之一。

## 决定

1. **不建数据库服务，不引入 SQLite 服务端。** 站点继续留 GitHub Pages。
   > 不是省钱，是**唯一不丢已有记录的形态**：学习记录按 origin 隔离，换域名即清零；
   > `ataotao.github.io` 是 `github.io` 子域，迁到任何别的托管都会换域。
2. **同步载体 = 一个私有仓**（不是站点仓、不是 gist）：**一台设备一份整份快照**。
   读 = 拉全部设备快照后合并；写 = 覆盖自己那一份（sha 乐观锁，冲突重试）。
   **按科隔离（2026-11-18 修复）**：三科是不同的训练器、不同的 localStorage 键，快照必须分层
   `devices/<科目>/<deviceId>.json`，deviceId 带科目前缀 `<科目>|dev-xxx`，合并时按科目过滤异科快照。
   否则共用 deviceId + 单一 `devices/` 目录会让物理同步把数学错题并进来、两科写回同一份互相覆盖。
   科目由构建期注入的 `LT_SUBJECT` 常量确定；无前缀的老快照仍可读（向后兼容）。
3. **认证 = fine-grained PAT**，只授该仓的 contents 读写，存本机浏览器。
   不用 device flow：OAuth App 发的 token 覆盖整个私有仓范围，**权限比一个细粒度 PAT 更大**，
   为了少填一次而放宽权限不划算。
4. **合并规则 = 事件并集**：`recs[]` 每条作答带 `ts`，按 `(ts, mod, kind, 题目标识)` 去重后取并集，
   统计**按事件重算**，不信任何设备自己算的百分比。
   **⚠ 两族题目标识不同（2026-11-18 review 更正）**：化学内核族 `recs` 写 `prompt`、无 `kn`
   （`工具/trainer/kernel.js:280`），去重键为 `(ts, mod, kind, prompt[:40])`
   （`kernel.js:155` `recSig()`，段二已落地）；物理/数学脚手架族 `recs` 写 `kn`、无 `prompt`
   （`物理/源/train.ui.js:790`、`数学/源/train.ui.js:683`），历史导出同此格式。
   段三落地必须**分族处理**：直接把内核族 `recSig()` 套到脚手架族，第 4 维恒为 `''`，
   会丢失同题去重能力。统一键形如 `(ts, mod, kind, prompt[:40] || kn)`，
   且需让物理/数学导入与云同步共用同一函数——它们当前的导入去重各写在
   `train.ui.js:1018/896`，是待收敛的重复实现。
   没有事件、只有累计计数的那几科（历史／道法／公式记背）只能按设备取 `max`，
   并标「不可合并」——**绝不求和**，求和会把同一次作答算两遍。
5. 可选写一份 `merged.json`，让训练台（本地只读面板）直接读合并结果，不必自己实现合并。
6. **同步是显式动作**（按钮 / 页面加载时拉一次），不是实时。没网时照常本地记录，下次联网补传。
7. **设备态不进载体。** 只搬「学习事实」——作答事件 + 错题本；`days`（按天派生的作答视图）、
   `lastRound`（上次出过哪些题的防重状态）、`dayPlan`（当天计划）留在设备上。
8. **历史导出作为独立「历史设备」上车**，不冒充本机；原始文件只增不改，合并结果由它重算。
9. **记录只存在私有仓，绝不进站点仓。** ADR-0006 的合并会让 `ataotao.github.io` 成为唯一仓，
   而那个仓**公开**（它对外发 Pages）。所以 `学习记录/` 在站点仓里只保留说明文档，
   真实作答数据（当前种子 + 以后的快照）一律进私有仓 `learning-records`。
   > 这条顶掉 ADR-0001 与 `学习记录/README.md` 里「本仓库是私有仓库」的假定——
   > 该假定在合并后不成立，而记录已入库过一次就会永久留在公开历史里，删不掉。

## 权衡过的方案

| 方案 | 否掉的理由 |
| --- | --- |
| Cloudflare Worker + D1（真 SQLite，可查询） | 需新增账号；`*.workers.dev` 在国内访问不稳；能查询是训练台的事，不值得为它起服务 |
| 家里 `NUCBOX_K9` 起 SQLite 服务 + Tunnel | 依赖家里机器在线；手机上可能还要挂客户端 |
| 只做「导出 → 云盘 → 导入」 | 摩擦仍在；但**合并逻辑要按本 ADR 做对**，因为它与载体无关 |
| Supabase / Firebase 等 BaaS | 不是 SQLite；境外访问；为了几十 KB 记录引入一整套认证 |

## 后果

- **好处**：零新增账号、零成本；记录天然有 git 历史；私有仓可 clone 给训练台读；
  与 ADR-0006 的单仓哲学一致（数据仓是**数据**，不是第二个代码仓）。
- **代价（明确认下）**：
  - PAT 存在浏览器 `localStorage`。泄露的最坏后果是「有人能改你的学习记录」，可随时吊销；
    这是为「零后端」付的价。
  - **同步不是实时的**：手机上做完，电脑上要等一次拉取才看见。要实时感就得回到方案表里的一、二。
  - 记录格式要带 `deviceId`，且载体文件只增不改历史（覆盖只覆盖自己那份）。
- **记录格式影响**：三科闪练卡的裸 DB `{v:1,recs,wrong,meta}` 需扩 `deviceId`
  （`lt.practice-records/1` 是历史／道法／公式等带外壳老工具的 schema，不在段三范围）；
  事件去重**不新增 `eventId`**（旧事件没有，会造成两套语义），靠决定第 4 条的分族复合键
  （内核族 `prompt[:40]` / 脚手架族 `kn`，统一函数取 `prompt[:40] || kn`）；
  模板迁移时顺手给每条记录补 `qid`（现在只有 `kn` 标题或 `prompt`，没有稳定题目标识），
  但去重键不依赖它。

## 不可回退的约束

1. **不求和**：合并绝不把累计计数相加。
2. `deviceId` 进入三科闪练卡的裸 DB 格式（否则合并只能"整份取最新"，会丢另一台设备的新增）；
   带外壳的 `lt.practice-records/1` 老工具 schema 不在段三范围。
3. 站点域名不变（换域 = 记录清零）。
